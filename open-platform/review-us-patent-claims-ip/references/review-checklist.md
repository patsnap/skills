# US patent claims review checklist

Use this reference for full reviews of US patent application documents, Office-action amendments, or complex claim sets. Re-check current USPTO guidance, statutes, regulations, binding precedent, and the actual prosecution record.

## 1. Matter identity and review scope

- [ ] User's question and intended decision recorded.
- [ ] Exact claim set/version/date recorded.
- [ ] Clean and marked-up versions distinguished.
- [ ] Source file/page/paragraph locator available.
- [ ] Application/publication/patent number recorded if known.
- [ ] Priority and filing dates recorded.
- [ ] Provisional/nonprovisional/continuation/divisional/CIP/reissue route identified.
- [ ] 35 U.S.C. 111(a) versus 371 national-stage route identified.
- [ ] Pre-AIA/AIA context identified where material.
- [ ] Prosecution stage, deadline source, and authority cutoff recorded.
- [ ] Review is pre-filing or post-filing.
- [ ] User's desired breadth and commercial embodiment captured.
- [ ] Legal-advice boundary stated.

## 2. Available materials

- [ ] Claims.
- [ ] Abstract.
- [ ] Full specification.
- [ ] Drawings.
- [ ] Examples/test data.
- [ ] Sequence listing/deposit information if relevant.
- [ ] Prior-art discussion/IDS.
- [ ] Office actions and cited references.
- [ ] Amendments/remarks/interview summaries.
- [ ] Filing history/prosecution record.
- [ ] Related family applications/claims.
- [ ] Target product/process evidence.
- [ ] Missing-material effect disclosed.

## 3. Technology-specific intake

- [ ] Software/AI architecture, data flow, training/inference, control and claimed technical improvement.
- [ ] Chemistry/materials composition, ranges, examples, test conditions, variability and effect.
- [ ] Biotech/pharma sequence/genus/species, assays, dose, treatment, mechanism and evidence.
- [ ] Diagnostics correlation, sample transformation, assay configuration and treatment steps.
- [ ] Mechanical/electrical structural relationships and drawing consistency.
- [ ] Telecom/standards claim mapping and standards-version evidence when relevant.
- [ ] Business-method actors, data sources, transactions and technical implementation.
- [ ] AI-assisted inventorship facts routed for current qualified review when relevant.

## 4. Claim extraction and inventory

- [ ] Every claim number captured.
- [ ] Exact text preserved.
- [ ] Claim status captured if available.
- [ ] Independent/dependent/multiple-dependent form identified.
- [ ] Statutory category identified.
- [ ] Parent claim(s) captured.
- [ ] Full dependency path generated.
- [ ] Amendment additions/deletions captured.
- [ ] Source locator captured.
- [ ] Duplicate or missing numbers flagged.
- [ ] Canceled/withdrawn/allowed/rejected claims distinguished.

## 5. Dependency graph and US form

- [ ] Every dependent claim references an existing preceding claim as required.
- [ ] Dependent claim further limits the parent.
- [ ] No circular dependency.
- [ ] Multiple-dependent reference is in the alternative only.
- [ ] Multiple-dependent claim does not depend from another multiple-dependent claim.
- [ ] Category transitions are legally and grammatically coherent.
- [ ] Incorporated limitations produce a complete claim.
- [ ] Claim count/fee implications flagged for current verification.
- [ ] Punctuation and single-sentence form reviewed.
- [ ] Antecedent articles and reference phrases consistent.
- [ ] Markush/alternative language reviewed.
- [ ] Product-by-process language identified.
- [ ] Intended-use and printed-matter/nonfunctional descriptive material issues considered.

## 6. Inventive-concept map

For each independent claim:

- [ ] Category.
- [ ] Actor or system boundary.
- [ ] Essential elements/steps.
- [ ] Apparent technical problem.
- [ ] Claimed mechanism.
- [ ] Claimed result/effect.
- [ ] Likely commercial embodiment.
- [ ] Apparent distinguishing limitations.
- [ ] Supporting specification locator.
- [ ] Uncertainty/assumption.

## 7. BRI review — pending examination context

- [ ] Broadest reasonable, not broadest possible.
- [ ] Interpretation consistent with specification.
- [ ] Ordinary/customary meaning considered.
- [ ] Express definitions identified.
- [ ] Drawings/context considered.
- [ ] Person-of-ordinary-skill perspective considered.
- [ ] Preamble limiting effect reviewed.
- [ ] Transitional phrase reviewed (`comprising`, `consisting of`, etc.).
- [ ] “Configured to,” “adapted to/for,” wherein/whereby clauses reviewed.
- [ ] Functional and result-oriented language reviewed.
- [ ] Intended-use limitations reviewed.
- [ ] Relative terms/ranges reviewed.
- [ ] Prosecution BRI distinguished from issued-claim litigation construction.

## 8. 35 U.S.C. 112(a) — written description

- [ ] Every limitation mapped to paragraph/page/figure/example/sequence.
- [ ] Independent claim breadth supported.
- [ ] Genus supported by representative species/common structure or other adequate disclosure.
- [ ] Ranges and endpoints supported.
- [ ] Alternatives/Markush group supported.
- [ ] Claimed combinations/subcombinations supported.
- [ ] Negative limitations have basis.
- [ ] Optional features supported.
- [ ] Functional results supported across claimed scope.
- [ ] Newly coined terms explained.
- [ ] Priority-document support reviewed when relevant.
- [ ] Amendment basis and new-matter risk logged.
- [ ] Claims-only review labeled preliminary.

## 9. 35 U.S.C. 112(a) — enablement

- [ ] Full claim scope considered.
- [ ] Technology predictability considered.
- [ ] Working examples considered.
- [ ] Guidance/direction in specification considered.
- [ ] Quantity of experimentation considered.
- [ ] Routine versus undue experimentation considered under current law.
- [ ] Functional genus breadth considered.
- [ ] Operability/utility concerns identified.
- [ ] Software/AI algorithm/architecture/data-flow disclosure reviewed.
- [ ] Chemistry/biotech/materials scope/examples/variability reviewed.
- [ ] Claimed effects tied to evidence and conditions.
- [ ] Unsupported broadening identified.

## 10. 35 U.S.C. 112(b) — definiteness

- [ ] Missing antecedent basis.
- [ ] Inconsistent terminology.
- [ ] Ambiguous pronouns/references.
- [ ] Terms of degree have objective boundaries.
- [ ] Relative terms have context/measurement.
- [ ] Optional/alternative language creates clear scope.
- [ ] Step order is clear where required.
- [ ] Actor for each step is clear.
- [ ] Mixed statutory category identified.
- [ ] Desired result is not the only boundary.
- [ ] Ranges are internally consistent.
- [ ] Units/measurement methods are clear.
- [ ] Translation artifacts reviewed.
- [ ] Definiteness conclusion is context-specific, not keyword-based.

## 11. 35 U.S.C. 112(f)

- [ ] “Means for” or “step for” language identified.
- [ ] Functional term without “means” identified.
- [ ] Structural meaning to skilled artisan assessed.
- [ ] Complete claimed function identified.
- [ ] Corresponding structure/material/acts located.
- [ ] Disclosure clearly linked to the function.
- [ ] All claimed functions covered.
- [ ] Computer-implemented function has adequate algorithm where required.
- [ ] Scope/equivalents consequence explained.
- [ ] Indefiniteness risk explained.
- [ ] Structural alternative proposed when supported and desired.
- [ ] Applicant intent is not treated as controlling.

## 12. 35 U.S.C. 101

- [ ] Current USPTO page/MPEP/guidance checked.
- [ ] Statutory category identified.
- [ ] Claim analyzed as a whole.
- [ ] Judicial exception, if any, identified.
- [ ] Step 2A Prong One analyzed.
- [ ] Step 2A Prong Two/practical application analyzed.
- [ ] Step 2B/significantly more analyzed when needed.
- [ ] Additional elements and ordered combination considered.
- [ ] Claimed technical improvement identified.
- [ ] Specification support for improvement located.
- [ ] Generic computer/data collection/output concerns reviewed.
- [ ] AI claim evaluated case-by-case, without magic words.
- [ ] Natural correlation/phenomenon/product issues reviewed for life sciences.
- [ ] Concrete treatment/preparation/assay/transformation features reviewed.
- [ ] Eligibility kept separate from 102/103/112.

## 13. 35 U.S.C. 102/103 — search-status gate

- [ ] `search_status` recorded: not executed, cited references only, or executed.
- [ ] No novelty/nonobviousness conclusion when search not executed.
- [ ] Conventional element aggregation reviewed structurally.
- [ ] Predictable combination/routine optimization risk reviewed.
- [ ] Result-only distinction reviewed.
- [ ] Technical mechanism/distinction identified.
- [ ] Dependent fallback limitations identified.

When references are supplied/searched:

- [ ] Reference identity/date verified.
- [ ] Prior-art eligibility checked for filing/priority/AIA context.
- [ ] Claim chart maps every limitation.
- [ ] Express/implicit/inherent disclosure distinguished.
- [ ] Inherency basis supported, not speculative.
- [ ] 103 combination rationale identified.
- [ ] Analogous-art issue considered.
- [ ] Reasonable expectation of success considered.
- [ ] Teaching away considered.
- [ ] Unexpected results/objective indicia considered.
- [ ] Nexus considered.
- [ ] Examiner assertion separated from verified disclosure.
- [ ] Missing limitation and counterargument recorded.

## 14. Claim architecture

- [ ] Broad independent claim captures the invention rather than environment.
- [ ] Independent claim covers target commercial embodiment.
- [ ] Independent claim does not omit the actual distinction.
- [ ] Independent claim does not include avoidable narrow details.
- [ ] Mid-level fallback claims exist.
- [ ] Narrow implementation fallback claims exist.
- [ ] Dependent claims meaningfully narrow.
- [ ] Parallel categories are commercially useful and supported.
- [ ] Actor placement is deliberate.
- [ ] Hidden/internal limitations minimized when possible.
- [ ] Easy design-arounds identified.
- [ ] Claim differentiation considered.
- [ ] Continuation/divisional/CIP plan considered.
- [ ] Double-patenting/terminal-disclaimer issue flagged for counsel where relevant.

## 15. Restriction and election

- [ ] 111(a) restriction versus 371/PCT unity route identified.
- [ ] Potential independent inventions identified.
- [ ] Potential related-but-distinct inventions identified.
- [ ] Product/process/apparatus/use groups identified.
- [ ] Genus/species groups identified.
- [ ] Design/operation/effect relationship considered.
- [ ] Burden and search/examination distinction considered.
- [ ] Linking/generic claims identified.
- [ ] Rejoinder potential considered.
- [ ] Election consequences considered.
- [ ] Divisional timing and 35 U.S.C. 121 issues routed to counsel.
- [ ] Restriction is not predicted solely from claim count.

## 16. Enforceability and infringement proof strategy

- [ ] Each limitation's observability assessed.
- [ ] Public documentation/testing/teardown evidence identified.
- [ ] Source-code/discovery dependence identified.
- [ ] Network/server-side proof dependence identified.
- [ ] Actor for every method step identified.
- [ ] Divided-infringement risk identified.
- [ ] Territorial/location issue identified.
- [ ] Product/system alternative considered.
- [ ] Internal intent/knowledge limitations identified.
- [ ] Design-around paths identified.
- [ ] Prosecution-history disclaimer/estoppel sensitivity considered.
- [ ] Review is not presented as an infringement opinion.

## 17. Amendment suggestions

For every proposed amendment:

- [ ] Claim number and exact text.
- [ ] Additions/deletions clear.
- [ ] Objective stated.
- [ ] Specification support locator.
- [ ] New-matter caution.
- [ ] BRI effect.
- [ ] 101 effect.
- [ ] 102/103 effect.
- [ ] 112 effect.
- [ ] Scope gained/lost.
- [ ] Actor/observability effect.
- [ ] Dependency impact.
- [ ] Prosecution-history/disclaimer risk.
- [ ] Dependent-claim alternative considered.
- [ ] Pre-filing addition distinguished from post-filing amendment.

Amendment action types:

- broaden by removing unsupported/unnecessary environment, UI, user, implementation or parameter language;
- clarify antecedent basis, objective standard, actor, sequence or structure;
- narrow strategically with a supported technical distinction;
- recast result language into mechanism/data flow;
- add a supported dependent fallback;
- add specification disclosure only before filing or through a legally appropriate new application route; and
- preserve alternatives for continuation/divisional strategy.

## 18. Issue-record completeness

- [ ] Unique issue ID.
- [ ] Severity.
- [ ] Category.
- [ ] Claim number(s).
- [ ] Exact quoted language.
- [ ] Claim source locator.
- [ ] Specification support locator.
- [ ] Authority/practice basis.
- [ ] Risk explanation.
- [ ] Confidence.
- [ ] Recommended action.
- [ ] Example supported language if useful.
- [ ] Scope trade-off.
- [ ] New-matter caution.

## 19. Severity calibration

- **High:** material rejection/support/definiteness/coverage/actor/form/new-matter risk.
- **Medium:** prosecution friction, obviousness vulnerability, weak fallback, 112(f) ambiguity, restriction exposure, or avoidable strategic narrowing.
- **Low:** clarity, style, optional architecture, formatting, or minor practice preference.

Severity is not probability. State confidence and missing facts.

## 20. Deliverable QA

- [ ] Overall assessment is preliminary and bounded.
- [ ] Materials/version matrix included.
- [ ] Claim-set map included.
- [ ] Priority issue table sorted by severity.
- [ ] Claim-by-claim review complete for agreed scope.
- [ ] Amendment strategy includes support locators.
- [ ] Example language is clearly illustrative.
- [ ] 102/103 search status visible.
- [ ] Current-authority cutoff visible.
- [ ] Missing materials and limitations visible.
- [ ] Counsel gates visible.
- [ ] No invented prior art, claim text, status, support, deadline, or legal conclusion.
- [ ] No unsupported persona/credential claim.
