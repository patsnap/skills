# Technology keyword expansion

## Purpose

Expand a user’s technical concept into a testable retrieval strategy. This reference supplies a method and illustrative seed terms; it is not an authoritative or exhaustive taxonomy.

## Expansion dimensions

For each concept, consider:

1. canonical name and spelling variants;
2. acronyms and expanded forms;
3. scientific synonyms and legacy terms;
4. components and subsystems;
5. materials and compositions;
6. manufacturing or experimental processes;
7. architectures and mechanisms;
8. functions and performance outcomes;
9. applications and operating environments;
10. IPC/CPC or domain classifications;
11. relevant non-English equivalents; and
12. exclusions, homonyms, and adjacent-topic noise.

## Query layers

- **Broad:** high-recall terminology plus tested classifications.
- **Balanced:** core concept combined with function, component, or application.
- **Precision:** title/abstract/claim restrictions and explicit exclusions.

Keep each layer and its result-review notes in the trace.

## Classification use

- Discover candidate IPC/CPC classes from relevant records or official classification sources.
- Sample records inside each class before adoption.
- Combine classifications with text when a class is broader than the target.
- Record classification edition/date when material.
- Never claim that a class boundary equals the technology boundary.

## Multilingual search

Use local-language legal names and technical terms when they materially improve recall. Keep them as literal query data and label the language. Do not translate legal names into invented assignee strings.

## Validation loop

1. Run a small broad sample.
2. Label relevant, adjacent, and irrelevant records.
3. Identify missed terminology and dominant noise.
4. Revise expansions/exclusions.
5. Retest against known relevant records and an independent sample.
6. Freeze the versioned query only after documenting limitations.

## Evidence requirements

Record the source of specialized synonyms, classifications, and exclusions. Acceptable sources include representative patent records, peer-reviewed reviews, standards, controlled vocabularies, and authoritative technical documentation.
