# 情报简报生成与解读

## 连接与使用

依赖 MCP 服务键 `eureka-pulse`；地址、认证和固定语言请求头以包内 `mcp.json` 及宿主实际加载的连接为准，本文不写死端点。工具说明与参数契约由 MCP 协议提供。此 Skill 保留业务操作、文件交接及报告规则；加入插件包本身不创建监控或定时任务，只有用户实际提出对应任务时才执行。

## 用户在什么情况下需要

- **研发工作需要持续了解进展**：已经关注某项技术或正在解决某个产品问题，希望定期知道出现了哪些新方案、研究成果和应用消息，决定哪些资料值得阅读或验证。
- **产品工作需要关注相关公司**：已经有关注的同行、合作方或产品，希望持续了解它们公开了哪些技术和产品动态，确定需要继续了解或跟进的事项。
- **定期整理资料占用时间**：需要每周整理同一范围内的新专利、论文和新闻，希望获得有重点、有来源、可以直接打开阅读的简报。
- **需要集中阅读月度进展**：希望把一个完整自然月内的相关资料整理为报告，了解本月有哪些值得阅读的新方案与消息。
- **已有关注内容发生变化**：需要增加或移除公司、改变技术范围、调整关注重点、查看某一期简报，或者停止定期跟踪。

## 用户可能怎样描述

| 用户的说法 | 需要理解的问题 | 执行入口 |

| “我们一直在研究连接器接触可靠性，有新方案或研究成果就定期整理给我。” | 技术问题涉及的产品范围、希望看到的方案与效果证据 | [创建跟踪](references/create.md) |
| “以后每周整理一下钠离子电池的新专利和论文。” | 已明确的主题范围和资料类型 | [创建跟踪](references/create.md) |
| “想持续了解这个方向，但还不知道应该关注些什么。” | 用户正在做什么工作，哪些变化会影响后续研究或行动 | [确定关注内容](references/create.md#步骤一确定监控问题) |

## 怎样理解和处理用户需求

1. **直接使用关注对象与范围**：用户给出公司及产品、明确技术主题或其他可以检索的范围时，直接进入参数生成。产品本身即可作为关注重点，按其完整范围处理；用户已经说明的用途和限制一并采用。
2. **采用默认报告周期与监控设置**：类型固定为个人 Pulse，监控计划按周运行；本次报告默认采用上一个完整自然月，用户明确要求周报或指定完整月份时采用其要求。资料范围使用参数生成工具返回的默认值。用户主动指定资料限制时完整保留。只有研究对象无法确定、主体存在实际歧义或已有要求互相冲突且无法自行解决时，才询问影响执行的必要内容。
3. **根据请求选择操作**：要求建立持续跟踪时进入创建模块；已有跟踪的查看和调整分别进入对应模块。只询问能关注什么、怎样设置时，完成需求说明后结束；只要求查看近期资料且尚无已有跟踪时，说明通过本 Skill 生成简报所需的创建操作，取得相应授权。
4. **说明用户会得到什么**：围绕其关注问题交付本期重点内容、具体资料和来源，生成可以直接打开的简报网页。能否判断进展、效果和变化取决于取得的证据，建议说明依据和适用条件。

需求理解、必要提问和参数准备由[创建模块](references/create.md)完整管理；入口中的例子用于识别用户意图，实际关注内容按本次需求确定。

## 内部执行与交付

- **执行来源**：通过 `eureka-pulse` 生成配置和周期解读；内置脚本整理已有内容并自动生成独立 HTML。报告中的事实、Summary、Insight 和建议均来自取得的服务结果。
- **执行顺序**：读取当前操作模块及其指定的公共规则，按[工具与文件调用](references/mcp.md)准备环境和执行目录，完成当前步骤的检查后继续交接。创建包含首期简报时持续执行到 HTML 交付。
- **意图输入**：参数生成只接收用户明确的关注对象、业务范围及具体分析要求；输入组织规则由[创建模块步骤二](references/create.md#步骤二生成与检查配置)统一管理。监控参数、本次报告请求和宿主定时任务分别处理。
- **统计展示与历史**：报告沿用 Python HTML 生成流程，交由[独立图表模块](references/charts.md)根据实际公司、技术或产品分类动态选择卡片与图表。少量有效项目显示卡片，需要多项比较时显示图表。月报自动调用[历史比较模块](references/history.md)读取包含目标月的最近十二个完整自然月，已有简报的周报读取包含目标周的最近八个完整自然周；用户指定窗口时采用其要求。每个维度有至少两个同定义且可统计的期次时，统一使用多系列折线图展示历史收录数量，每个公司或分类对应一条曲线；配置版本、历史检索范围或评分规则没有返回时保留解释限制，继续展示实际数量。某个维度只有单期有效资料时显示该期分布，其他维度继续处理。历史缺失期次保持缺失，不自动触发生成。目标期缺失时可交付明确说明状态的历史报告。
- **执行记录**：保存当前步骤、已有结果和继续条件；调用结果不确定时核实原操作。请求范围内的结果全部完成后结束。
- **图表维度与排列**：通过[图表维度选择模块](references/chart-selection.md)选择公司趋势、最高有效字段 `level` 对应的分类趋势，以及公司交叉图；没有 `level` 时由 AI 按监控问题排列字段重要性并保存理由。交叉字段按技术路线、产品线、其他技术字段顺序选择。两个趋势图先展示，桌面一行两个，交叉图在下方使用完整可用宽度。没有时间轴的图表汇总统计范围内全部有效资料，跨期相同资料按稳定身份去重。
- **顶部统计卡片**：按[顶部统计卡片模块](references/overview-metrics.md)从目标期真实资料中选择四至五个有效指标，保留重点解读与高相关技术，再补充主体和分类等数量。没有解读结果的字段省略，部分解读说明覆盖数量，有效指标不足时保留实际数量；项目数量与资料条数分别核对来源。
- **资料交接**：原始 MCP 响应按调用保存，后续通过文件路径和 SHA-256 引用；使用内置入口准备报告输入，渲染期间只读来源文件。

## 共同要求

- 获取简报配置详情 `get_mcp_brief_info`、目标期详情 `get_mcp_brief_data` 及历史期次时，按 [详情请求的程序入口](references/mcp.md#详情请求的程序入口)选择当前宿主支持的调用方式，由实际 HTTP 连接发送 `X-Site-Lang: CN` 并检查对应响应。豆包原生连接按公共模块配置 Header，认证由豆包管理；SDK 文件调用使用统一 HTTP 发送层。当前入口缺少可用连接或无法确认已保存的语言设置时停止执行，保留继续所需条件。
- 使用个人 Pulse，固定 `pulse_type=PERSONAL_MCP`；监控计划配置保持 `period_type=week`。报告目标独立记录 `period_type=month|week`，读取与运行请求使用报告目标的周期。
- 创建或生成报告默认采用上一个完整自然月，使用 `YYYYMM` 编码并覆盖该月第一日至最后一日。明确要求周报时采用上一个完整自然周，周日开始、周六结束，使用 `YYYYWW`。用户指定其他已结束的完整自然周期时采用指定周期；明确只保存配置时完成配置保存即结束。
- 用户建立持续跟踪时设置 `scheduled_run_enabled=true`，取得真实监控 ID 后调用[每周定时任务模块](references/schedule.md)创建或复用对应的宿主任务；当前会话按报告请求生成月报。单次报告与仅读取已有结果使用各自的请求范围。
- 关注对象和范围明确后直接生成参数；资料范围沿用参数生成工具返回的默认 `data_scope`，用户明确的资料限制在生成输入中保留。
- 创建时默认显示高相关技术明细，按[重点规则与资料审核](references/focus.md)配置符合用户问题的重点技术动态；完整性检查覆盖原始结果中的全部高相关记录。
- 用户要求报告时交付 HTML；明确要求原始数据或 JSON 时按其要求交付。
- 最终 HTML 文件名包含报告主题、日期范围和报告类型，按[文件命名规则](references/html.md#步骤二自动生成)生成，并交付脚本返回的实际文件路径。
- 修改只覆盖用户要求和必要关联字段，提交 Tool 要求的完整配置；保留其余当前配置和定制。
- [HTML 生成](references/html.md)使用本 Skill 内置的模板、基础样式及五套配色生成独立报告；每次生成检查页面结构、引用目标、资料完整性与来源校验值。样式和交互检查在维护模板、CSS 或 JavaScript 时执行。
- [报告配色](references/themes.md)负责按名称选择华为红、科技蓝、生态绿、砚紫、石墨金五套色系；未指定时采用科技蓝，明确要求沿用已有报告配色时读取其记录的色系并核对可用名称。多个配色版本复用同一份资料与统计。
- 程序异常立即停止依赖步骤。保留真实错误、当前执行位置及继续所需条件，不重复创建或重复触发同一期任务。
