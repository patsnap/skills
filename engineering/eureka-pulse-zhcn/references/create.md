# 创建监控

## 目标与输入

- **目标**：把用户关注的问题转为可执行监控配置，保存监控，并完成本次要求的首期简报。
- **输入**：用户提供的公司、技术或产品范围，以及已经明确的资料限制、排除条件、计划运行要求和目标自然月或自然周。监控计划按周运行，本次报告默认采用月报；用户指定的说明和定制完整保留。
- **公共规则**：读取 [MCP 与文件管理](mcp.md)。参数结构以当前目标创建 Tool 的 schema 为准。

## 执行步骤

### 步骤一：确定监控问题

1. **采用用户提供的关注范围**：公司及产品、明确技术主题或其他可以检索的范围，均可直接进入步骤二。产品名称本身就是关注重点；以完整产品范围生成参数。已提供的用途、应用、技术限制和资料要求完整保留，普通简称交由参数生成工具识别。
2. **判断是否确有执行阻断**：仅在研究对象无法确定、同名主体无法唯一识别，或用户要求互相冲突且无法依据现有信息解决时询问。已经明确的公司和产品范围直接采用；资料选择、每周频率、个人 Pulse 类型均按固定规则处理。
3. **处理未提供的可选信息**：资料范围沿用参数生成工具返回的默认 `data_scope`。混淆项、新闻主题及解读内容在取得基础参数后，根据当前业务范围检查配置；用户未提供的可选要求保持未指定状态。调用创建工具前简要告知用户可以补充混淆项和新闻主题，并继续执行；明确没有混淆项时允许 `easy_to_be_confused=[]`。
4. **确定本次任务并保存需求**：区分仅讨论关注内容、仅准备参数、仅保存配置，以及建立持续跟踪并交付首期报告。仅讨论需求时，交付关注对象和可采用的内容，在当前步骤结束；执行任务时将完整需求保存为 `requirements.json`，包含 `user_request`、`intent_input`、`objective`、`subjects`、`scope`、`exclusions`、`news_topics`、`confused_technologies`、`pulse_type`、`period_type`、`scheduled_run_enabled`、`report_request`、`schedule_request` 和 `custom_requirements`。`user_request` 保留用户原话，`intent_input` 保存步骤二准备的业务需求文字；其他可选业务信息缺失时保持为空，监控设置为 `PERSONAL_MCP` 和 `week`。
   - 用户要求持续定期监控时设置 `scheduled_run_enabled=true`；仅准备参数、仅保存配置或单次报告使用 `false`。用户有明确设置时使用其指定值。
   - `report_request` 保存本次报告的 `period_type`、`period` 与 `action`。默认 `period_type=month`，未指定月份时交给报告模块计算上一个完整自然月；用户明确要求周报时设置 `week`。`action=generate` 表示创建首期或明确生成目标期，`action=view` 表示仅读取已有结果。完整日期由报告模块写入 `target.json`；监控配置中的 `week` 保持原值。
   - `schedule_request` 保存宿主每周任务的创建要求、用户已提供的触发时间和时区。建立持续跟踪时登记创建要求；实际任务由[每周定时任务模块](schedule.md)处理。仅准备参数、仅保存配置、单次报告及仅读取结果按当前授权记录相应操作。

### 步骤二：生成与检查配置

1. **准备意图输入**：根据用户原话及其已明确的业务补充，组织参数文件中的 `input` 字符串，并保存到 `requirements.json` 的 `intent_input`。
   - **业务内容**：写明关注的公司、技术或产品；用户明确提出的分析问题、应用边界、资料限制、排除条件和业务用途完整保留。每项内容都需要能够追溯到用户提供的信息。
   - **未指定内容**：用户没有指定资料类型、新闻主题、监控目的或排除范围时，省略对应语句。资料范围采用参数生成工具的默认返回值；通用的“判断哪些资料值得阅读或跟进”等说明不作为补充需求。
   - **执行信息**：个人 Pulse 类型、周计划、`scheduled_run_enabled`、本次报告月份与生成动作、宿主定时任务，以及输出语言要求分别交给后续参数处理、报告模块、定时任务模块和 MCP 连接处理，均不追加到 `input`。
   - **请求检查**：逐项核对 `input` 与 `user_request` 及用户业务补充的对应关系，删除自行增加的范围和通用说明。用户只提供“关注华为技术有限公司的手机产品”时，请求为 `{"input":"关注华为技术有限公司的手机产品"}`。
2. **调用参数生成**：按 [MCP 请求语言](mcp.md#mcp-请求语言)检查实际调用连接，将已经核对的 `intent_input` 原样写入参数文件的 `input`，调用 `generate_mcp_brief_params_from_intent`。保存完整请求与原始响应，并按该模块核验服务生成语言；通过后继续配置处理。
3. **设置监控参数**：按[重点规则模块步骤一](focus.md#步骤一从监控问题确定规则)形成与当前需求对应的 `focus.json`，调用 `python scripts/monitor.py configure --input <参数响应.json> --focus <focus.json> --output <创建参数.json>`。程序保留资料范围和主题背景，设置个人类型、每周周期及计划运行，并默认开启技术明细、写入重点规则。建立持续跟踪时采用 `scheduled_run_enabled=true`；参数生成工具已有完整适用规则时可直接检查采用，缺少规则时需要补充后继续。仅保存配置或单次报告时增加 `--scheduled-run-enabled false`。按照创建 Tool 当前 schema 检查其余必填字段。
4. 根据用户问题检查以下内容，必要时修改当前参数对象：
   - **检索范围**：主题、公司、技术边界和排除条件是否覆盖用户需求；新闻主题是否可以用于持续检索。
   - **证据字段**：`ai_fields` 的每个字段说明提取什么、根据什么资料判断、输出格式、适用资料类型和缺失时的表达；枚举明确单选或多选及允许值。
   - **重点规则**：`typical_filters` 必须覆盖本次监控问题，明确入选条件、比较基准、证据要求和展示字段；按照[重点规则模块](focus.md)判断，资料不足时说明缺少什么。
   - **目录与卡片**：`detail_module.visible=true` 且模式能够显示明细，`card_fields` 承载用户需要阅读的信息；字段名与标准字段或 AI 字段一致。标题和来源身份由 HTML 模块统一显示；分类无法确定的高相关记录仍须显示，并说明分类待核实。
   - **总结角度**：`summary_angle` 说明本期需要回答的问题，区分公开事实、来源观点和推断；建议须有依据和适用条件。
5. 检查结论的适用范围：专利公开说明公开方案，论文结果保留实验条件，新闻保留来源及事件阶段；没有记录只能说明当前检索结果。趋势或历史变化需要已经取得的可比历史。
6. 按当前 schema 检查完整参数。无业务用途的数组和对象仅在 schema 允许且含义明确时为空；不为填满必填字段增加监控范围。用户只要求参数时交付参数文件并结束。

### 步骤三：保存监控并继续

1. 使用 `create_personal_mcp_brief`，从完整参数文件提交一次请求。
2. 保存真实响应和返回的 `pulse_id`。响应缺少可验证身份或结果未知时，按 [调用结果处理](mcp.md#调用结果处理)核实；不以同名旧记录作为新建成功依据。
3. 用真实返回 ID 调用 `get_mcp_brief_info`，保存完整原始响应作为最新配置来源。需要独立业务配置文件时使用 `monitor.py extract --kind config`，保留外层 `pulse_id`、类型、版本信息和完整显示配置；原始响应保持原样。
4. 建立持续跟踪且周计划已启用时，将真实 ID、已读取配置、`schedule_request` 和执行目录交给[每周定时任务模块](schedule.md)，接收实际任务 ID、计划和状态。模块缺少必需时间信息时保留待完成项，当前首期报告继续执行。
5. 只保存配置的请求在此交付名称、ID、类型和计划运行设置。其他创建请求携带当前配置、ID 和 `report_request` 进入[周期简报](report.md)，在当前会话触发本次要求的月报或周报。

## 输出、检查与交接

- **配置产物**：需求、意图请求、完整创建参数、原始响应、真实 ID 和取得的完整配置，以及持续跟踪对应的宿主任务结果，保存在本次执行目录。
- **通过条件**：意图输入仅包含用户提供的业务需求，执行信息由对应模块处理；用户要求均有配置承载；技术明细开启且重点规则完整；服务返回成功且身份明确；类型与计划运行设置符合用户要求。持续跟踪的宿主定时任务取得实际创建或复用结果，未完成事项明确保存。
- **报告交接**：写入 `state.json` 的当前步骤和配置路径，继续报告模块。配置保存成功与 HTML 完成分别记录。
