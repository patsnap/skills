# 每周定时任务

## 目标、输入与职责

- **目标**：为用户建立的持续跟踪创建或复用宿主每周任务，定期执行对应监控的周报流程。
- **输入**：真实 `pulse_id`、创建或更新后读取的完整配置、`requirements.json` 中的 `schedule_request`、用户时区及执行目录。
- **执行范围**：建立持续跟踪且 `scheduled_run_enabled=true` 时执行。单次报告、仅读取结果和仅保存配置分别遵守当前请求；已有任务的继续、暂停与删除由本模块统一处理。
- **结果分别保存**：服务端周计划通过配置读取核实；宿主任务通过任务工具返回结果核实；本次报告通过 `report_request` 和 `target.json` 确定周期。

## 执行步骤

### 步骤一：确定已有任务与每周时间

1. **检查宿主能力**：发现当前宿主提供的任务或自动化工具，读取当前参数说明；使用宿主正式接口处理任务。Codex 使用 `automation_update`，任务查询遵守该工具当前提供的说明；Eureka Desktop 和豆包使用各自当前提供的任务能力。
2. **定位已有任务**：根据真实 `pulse_id`、当前用户与宿主任务记录查找同一监控的每周任务。结果唯一且任务内容一致时直接复用；需要调整时修改原任务。创建结果未知时查询原操作，核实后继续。
3. **确定执行时间**：采用用户已提供的每周日期、时间和时区，或宿主已经明确保存的适用默认时间。创建接口需要时间而现有信息不足时，一次询问缺少的日期与时间，保存待完成状态；当前会话的首期报告继续执行。用户时区采用宿主明确提供的当前值。

### 步骤二：创建并核实每周任务

1. **组织任务内容**：写入真实 `pulse_id`、Skill 的可读取位置及本次执行结果位置。任务每周执行一次，在触发时根据用户当地日期计算上一个完整自然周，以 `report_request.period_type=week`、`action=generate` 进入[报告模块](report.md)，取得完整结果并交付有意义文件名的 HTML。每次使用新执行目录，计算当次目标日期；同一期已有完整结果时直接复用，缺失历史期次保持缺失，MCP 原始响应按调用保存。
2. **提交宿主任务**：通过当前宿主工具创建一次任务；已有匹配任务时按步骤一处理。遵守宿主对当前会话任务、通知和执行环境的要求。任务执行说明保持完整、可读，日期与频率使用工具要求的计划参数提交。
3. **读取实际结果**：核对任务 ID、启用状态、每周计划、时区与真实监控 ID；宿主支持读取或查看时再次读取。只取得配置中的 `scheduled_run_enabled=true` 时，宿主任务状态保持未核实。任务能力缺失、时间不足或创建失败时，保存具体原因和继续所需条件。
4. **保存并交接**：将 `pulse_id`、`schedule_status`、真实任务 ID、任务计划、时区、宿主名称与工具结果引用保存到 `schedule.json`，通过 `state.json` 的文件引用交回创建或管理模块。当前月报继续使用原来的月目标；每周任务在以后实际触发时独立计算周目标。

### 步骤三：维护已有任务

1. **继续跟踪**：配置读取确认周计划已开启后，复用并恢复对应宿主任务；任务不存在且用户要求持续跟踪时，执行步骤一和步骤二。
2. **暂停跟踪**：暂停已唯一定位的宿主任务，读取实际状态，并保存结果。服务端配置与宿主任务任一操作失败时，分别说明其当前状态及继续条件。
3. **删除监控**：按用户已经授权的删除范围，暂停或删除对应宿主任务，保存结果并交回管理模块继续删除监控。查询确认任务不存在时保留查询依据。

## 输出与完成条件

- **输出**：`schedule.json`、宿主任务的真实工具结果，以及当前状态和必要的继续条件。
- **完成条件**：已创建或复用的任务具有真实 ID、启用状态和符合用户要求的每周计划；任务内容对应正确监控及周报流程。交付分别说明当前报告、服务端周计划和宿主任务的实际结果。
