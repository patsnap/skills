# 历史资料比较

## 目标、输入与职责

- **目标**：使用已有简报的真实历史结果，回答近期收录情况、高相关技术数量及关注方向的分布问题，帮助用户确定需要继续阅读的资料。
- **输入**：当前完整配置原始响应、自然月或自然周的 `target.json`、执行目录。月报默认窗口包含目标月及之前十一个完整自然月；周报默认窗口包含目标周及之前七个完整自然周。用户明确要求其他范围时采用其要求。新建简报的首期月报同样读取已有历史，首期周报默认使用本期资料。
- **职责**：本模块负责窗口计算、历史读取、来源登记、可比性检查与统计；[图表模块](charts.md)独立负责绘图及图表检查。报告模块传入文件，接收本模块的完整结果后继续生成报告。
- **边界**：历史阶段只调用 `get_mcp_brief_data`。缺失期次保持缺失，不调用任何运行接口；权限、参数、服务及分页错误保留真实响应并停止依赖步骤。历史统计与服务端文字 Summary、Insight 分别组织。

## 执行步骤

### 步骤一：确定历史窗口

1. **接收当前目标**：通过实际用于历史查询的同一 MCP 连接读取 `get_mcp_brief_info`，确认简报身份及当前用户环境。配置、目标和历史响应须来自同一服务环境；切换客户端时重新核验连接及目标，不能把其他连接返回的不存在直接当作原简报缺期。核对配置与目标为同一 `pulse_id`，周期为已经结束的完整自然月或自然周。窗口以目标期为结束，按月份或周日日期计算跨年期次。
2. **生成读取清单**：执行以下命令，接收实际清单路径和逐期完整参数文件。程序根据目标周期选择默认十二个月或八周；需要其他范围时，月报增加 `--months <月份数量>`，周报增加 `--weeks <周数>`，两种参数分别用于对应周期。月度参数使用 `period_type=month` 与 `YYYYMM`，周度参数使用 `period_type=week` 与 `YYYYWW`。

   ```bash
   python scripts/history.py plan --config <配置原始响应> --target <target.json> --output <执行目录>/history/plan.json
   ```

3. **复用已有任务**：清单已存在时直接读取，继续其中 `pending` 期次。已取得的目标期响应直接登记，不重复读取；其他已有响应须核实身份、日期及来源校验值后复用。配置版本仅核对响应实际返回的值，缺失时保持未知。

### 步骤二：读取与登记历史资料

1. **逐期读取结果**：按清单中的 `arguments` 文件，通过 [MCP 文件调用入口](mcp.md#从文件提交完整参数)提交 `get_mcp_brief_data`。按 [MCP 请求语言](mcp.md#mcp-请求语言)核验本次入口，历史窗口内每个月或每周的详情读取均通过发送 `X-Site-Lang: CN` 的 HTTP 连接执行；恢复或切换连接时重新检查。完整参数与原始响应保存要求沿用公共模块。查询数量以计划期次为限，缺少某一期时继续查询窗口内其他期次。
2. **登记实际响应**：每取得一期，执行以下命令；程序检查原始响应并登记来源路径与 SHA-256，清单中的参数文件保持不变。

   ```bash
   python scripts/history.py attach --plan <history/plan.json> --period <六位月份或周编码> --response <完整原始响应>
   ```

   - `available`：身份、日期及返回的记录集合通过检查，可以统计已经完整返回的资料类型。
   - `missing`：成功业务响应明确为空，服务明确返回 `NOT_FOUND`，或已核实的 `error_code=90112044` 且内部错误为 `Data not existing`。保留响应原有错误码和状态，不生成零值。
   - `unavailable`：响应没有完整日期或可统计记录，不能确认目标期完整统计范围。保留实际原因，不将其计为零。
   - 调用错误、任务未完成、失败任务、身份或日期不符、分页缺失及记录冲突立即报错。错误响应继续保留，不能登记成缺失或触发补跑。
3. **保存继续位置**：通过公共 `monitor.py state` 写入 `step=history`、清单路径和未完成期次。历史窗口仍有 `pending` 时，继续读取，不能提前生成统计。

### 步骤三：检查比较条件并统计

1. **选择有业务意义的维度**：AI 根据本次监控问题检查配置中的分类字段、枚举和提取要求，选择需要观察的技术、产品或应用方向。指定字段使用后续命令的 `--dimension-field <field_key>`，可以重复传入。未指定时程序汇集当前配置与各期配置子目录或卡片已经使用且具有枚举定义的 AI 字段，再从每期自己的全局定义读取这些字段；卡片显示字段变化不影响已有分类定义的比较。实际没有分类值的字段不展示，文本描述不自动转成分类。公司维度从各类资料真实公司字段生成：专利申请人、论文机构、新闻涉及公司分别统计；缺少公司信息时省略对应维度。禁止根据标题或摘要猜测分类及公司关系。
2. **核对跨期依据**：使用每期响应实际返回的 `basic_info.pulse_id`、起止日期、记录集合、评分及 `basic_info.template_custom.ai_fields`。同一简报、同一周期类型、身份和日期有效的多个期次进入历史统计；监控范围、评分规则及配置版本缺失时继续统计各期收录情况，保留解释限制。不能用当前配置填补历史定义或宣称历史检索条件一致。
   - **收录数量与公司分布**：使用完整返回的各类记录与真实公司字段，专利申请人、论文机构、新闻涉及公司分别处理，公司统计不依赖相关性评分。配置版本没有返回时仍然展示历史数量。仅按实际标准名称归并公司，不推断公司关系。
   - **高相关数量与分类分布**：统一采用原始 `score >= 4`，并检查字段定义的 `data_scope`。按专利、论文分别记录评分完整性、已分类数量、适用数量和分类成员。某种类型缺少评分时，该类型的高相关总量保持未知，该类型不进入完整分类统计；其他类型继续处理。跨期合并分类时，使用参加比较的各期均评分完整的共同资料类型，说明参加和省略的类型。
   - **字段定义比较**：使用各期自己的 `field_key`、`data_format`、`data_scope`、`data_fields`、`enum_options`、`extraction_requirement` 及其他业务定义。`display_name`、展示优先级 `level` 与上述数组的排列顺序不改变比较结果；卡片样式和展示顺序不进入定义比较。分类含义或提取要求变化时，仅相应维度的不同定义期次保留空缺。字段没有实际分类值时保持未知；某分类未出现且该期分类覆盖不完整时，不将该分类计为零。
   - **数量解释与时间曲线**：至少两个有效期次时使用多系列折线图，表达各期已收录资料，每个公司或分类对应一条曲线。范围、评分规则或配置版本未知时保留解释限制，继续展示实际数量，不自动计算跨期增长率；曲线不表示检索条件已经确认一致。缺失或不同定义的位置保持断开，未知数量保持空缺。
3. **生成确定性统计**：执行以下命令。程序合并普通资料与重点资料中的相同稳定记录，同一期内只计一次；同一记录跨月或跨周被收录时分别计入对应期次的“收录数量”。月报直接读取各自然月响应，月份天数按日历计算；不同周期的数据分别统计。仅统计实际返回且通过完整性检查的资料类型；未返回类型保持未知。

   ```bash
   python scripts/history.py build --plan <history/plan.json> --output <执行目录>/history/statistics.json
   ```

4. **解释证据范围**：数量描述简报收录情况。分析明显变化时检查对应月份或周次的具体记录；研发投入、技术实力或商业进展需要对应证据。分类为多值时，一条资料可进入多个方向，不能直接把方向数量相加作为资料总量。图表模块不自行生成因果解释或建议。

### 步骤四：生成图表并交接报告

1. 调用[图表模块](charts.md)，传入 `statistics.json` 与图表输出路径，接收 `charts.json`。
2. 返回清单、统计和图表文件的实际路径，以及可用、缺失和不可统计期次。报告模块通过 `monitor.py prepare-report --charts <charts.json>` 引用结果。
3. 目标期有完整资料时，一并传入 `--data` 生成本期明细与历史图表；目标月或目标周缺失或不可统计时，仅传配置、目标与图表，生成明确说明目标期状态的历史比较报告。历史窗口无可用资料时，页面说明实际查询范围和状态，不生成空白图表。
4. 图表模块逐个维度检查有效期次，至少两个同定义且可统计的期次使用多系列折线图展示历史数量；只有一个有效期次时显示该期分布，并标注来源日期。目标期缺少某个字段时，其他历史期次中的有效维度继续处理。曲线、图例、来源交互及显示检查由图表模块统一管理。主报告仍由 Python 生成，卡片及图表由独立 JavaScript 模块生成；不要求 Python 提供另一套绘图实现。

## 输出与检查

- **正式产物**：`history/plan.json` 保存目标、来源引用、逐期参数文件与状态；月窗口使用 `months`，周窗口使用 `weeks` 表示期数，其余结构一致。`statistics.json` 保存各期数量、对应记录键、分类定义、比较依据及资料标题和来源。字段维度的 `components` 按资料类型保存完整性、成员、覆盖数量及缺少评分数量；维度及各类型的 `eligible_members` 保存实际适用记录键，供无时间轴图表跨期去重；`comparison_basis` 仅保存响应实际返回的配置版本。统计与图表数据使用 `schema_version=3`，旧派生文件通过原始响应重新生成，原始响应与读取清单保持原样。`charts.json` 由图表模块生成。
- **检查标准**：全部计划期次均有实际响应依据；所有来源校验值一致；窗口连续且包含目标期，月份起止日期与日历一致；图表数量和数值能够追溯到去重后的记录；缺失与未知保持空缺；历史阶段触发任务数为零。
- **历史展示验收**：对每个维度，核对真实有效期次与浏览器实际展示期次一致。至少两个有效历史期次时必须展示历史数量图，缺少配置版本不得使其只显示目标期。配置定义、评分完整性和来源期次的差异仅影响相应维度或资料类型；检查文件保留实际参加比较的类型、分类覆盖数量及排除期次的原因。
- **原始内容**：MCP 原始响应保存在公共调用目录中，统计仅生成派生文件。任何输出路径都不能覆盖配置、目标、清单来源或原始响应。
