# 选择图表分析维度

## 目标、输入与职责

- **业务目标**：让读者先看到公司及重要分类的时间变化，再查看公司在技术或产品方向上的资料分布，确定需要继续阅读的方向和来源。
- **输入**：用户的监控问题、当前配置原始响应、历史或当期统计文件。分类字段使用真实 `ai_fields`，数量和覆盖情况使用实际记录，不从标题或摘要重新推断分类。
- **职责**：AI 识别字段的业务角色并按监控目的排列重要性；`scripts/chart_selection.py` 检查实际字段、有效资料及 `level`，输出确定的展示维度；图表模块负责图形和页面生成。
- **输出**：AI 保存 `chart-selection.json`；图表入口输出带有选择结果和来源校验值的 `charts.json`，报告继续使用同一文件。

## 执行步骤

### 步骤一：识别实际分类字段

1. **确认候选字段**：读取配置的字段名称、数据格式、枚举、提取要求及实际返回的分类值。只登记真实存在且适合分类统计的枚举字段；自由文本不转换为分类。
2. **确定业务角色**：根据字段定义与用户问题，为每个适用字段登记以下一种角色；角色保存在本地展示文件中。
   - `technology_route`：描述技术手段、解决路径或技术方向。
   - `product_line`：描述产品系列、产品线或具体产品方向。
   - `technical_field`：其他能够回答监控问题的技术分类，例如技术层级、应用方向或关键部件分类。
3. **排列分析重要性**：说明用户需要了解什么变化，各字段怎样回答这个问题，以及实际分类覆盖是否足以支持分析。将全部已登记字段按重要性写入 `priority_order`，用 `priority_reason` 保存业务依据；不根据图形外观或数值较多就认定业务重要性更高。

### 步骤二：选择三个展示位置

1. **公司趋势**：优先使用有真实资料的专利申请人；没有申请人数据时，继续检查论文机构和新闻涉及公司。维度保留真实来源名称与资料类型，不推断机构归属或公司关系。
2. **重要分类趋势**：
   - 优先选择能够形成有效历史比较的枚举分类。没有多期资料时，按原有范围统计规则展示实际分布，不生成时间曲线。
   - 存在实际返回的字段 `level` 时，选择数值最高的有效字段；数值须有限且格式明确，不能把缺失值当作零，也不能补写服务端字段。
   - 最高 `level` 相同时，使用 AI 的重要性顺序选择一个字段。有效字段均没有 `level` 时，直接使用 `priority_order` 和业务依据选择一个字段。
   - 字段名包含“层级”不等于具有更高 `level`。`level` 只影响展示选择，不改变字段提取含义，不进入历史分类定义的比较。
3. **公司交叉图**：按 `technology_route`、`product_line`、`technical_field` 的顺序检查真实候选。技术路线没有字段、没有实际分类值或无法与真实申请人建立记录交集时，继续检查产品线，再检查其他技术字段。同一角色存在多个有效字段时按 AI 重要性顺序选择。仅生成一个有真实交叉资料的气泡图。
4. **检查展示用途**：分类趋势和交叉图可以选择同一字段，分别回答时间变化与统计范围内分布的问题。其余候选继续保留在统计文件中，不重复生成额外分析图；报告中的资料、引用与完整性检查继续完整执行。

### 步骤三：保存选择并生成报告

1. **保存本地选择文件**：以下示例中的字段键必须替换为本次配置实际返回的字段；角色与优先顺序由本次需求分析确定。

   ```json
   {
     "schema_version": 1,
     "fields": [
       {"field_key": "tech_route", "role": "technology_route"},
       {"field_key": "product_line", "role": "product_line"},
       {"field_key": "technology_level", "role": "technical_field"}
     ],
     "priority_order": ["tech_route", "product_line", "technology_level"],
     "priority_reason": "本次监控重点是技术方案及其方向变化，其次关注产品系列，最后观察创新发生的技术层次。"
   }
   ```

2. **生成展示结果**：历史统计与当期统计都传入同一选择文件。选用的字段须已进入统计；需要显式限定字段时，通过统计入口的多个 `--dimension-field` 保留全部候选。

   ```bash
   python scripts/charts.py --statistics <history/statistics.json> --selection <chart-selection.json> --output <history/charts.json>
   ```

   ```bash
   python scripts/charts.py --config <配置原始响应> --data <周期原始响应> --target <target.json> --selection <chart-selection.json> --output <charts.json>
   ```

3. **交接报告输入**：使用 `monitor.py prepare-report --charts <charts.json>` 保存报告输入引用，再按 HTML 模块生成。新报告使用选择文件完成维度选择；仅重新渲染时继续引用已有选择来源。选择文件内容发生变化时重新生成图表数据和报告输入，原始 MCP 响应保持原样。

## 输出与检查

- **来源**：`charts.json.selection_source` 保存选择文件路径与 SHA-256，原始配置及周期响应继续独立保存；程序重新读取选择文件与真实资料核对结果。
- **维度结果**：`dimension_selection` 保存公司趋势维度、分类趋势维度、分类趋势采用的依据及真实 `level`、公司交叉字段与角色、AI 业务理由及候选的有效期次。
- **排列**：两个趋势图先展示，桌面一行两个，间距 24px；小于 1024px 时纵向排列。公司交叉图在趋势图下方使用完整可用宽度。数据不足时保留实际可生成的图形，不生成空白面板或无依据曲线。
- **完成检查**：核对路线、产品线、其他技术字段的选择顺序，最高有效 `level` 或 AI 选择依据，两个趋势图的位置和下方交叉图。逐项核对图形数值、期次、来源点击及桌面、手机和打印；缺少真实 `level` 的情况单独记录测试范围。
