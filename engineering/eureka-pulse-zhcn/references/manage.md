# 管理监控

## 目标与输入

- **目标**：准确定位已有监控，完成用户指定的查询或修改，并核实结果。
- **输入**：用户指定名称或 ID、操作及修改内容；目标为个人 Pulse。
- **公共规则**：读取 [MCP 与文件管理](mcp.md)。

## 执行步骤

### 步骤一：定位与查询

1. 将用户指定对象和操作目的交给[目标定位入口](mcp.md#目标定位与配置来源)，接收实际身份及当前操作需要的完整配置。
2. 列表查询交付名称、说明、类型与 ID；查看配置交付实际配置内容及其说明。
3. 修改或生成报告时保存该入口取得的最新完整配置，继续对应步骤。

### 步骤二：修改与计划运行

1. 以刚取得的完整配置为修改依据，保存用户要求及修改字段。公司、新闻主题、目录和显示字段等局部修改直接调整当前对象。
2. 核心主题或整体范围变化导致原主题分析失效时，调用参数生成工具，按[创建模块步骤二](create.md#步骤二生成与检查配置)检查配置，并保留仍然有效的用户定制。
3. 用户说“继续每周整理”“暂停跟踪”“以后不用定期整理”等时，通过 `scheduled_run_enabled` 开启或关闭计划运行。用户明确要求删除监控时进入步骤三；不承诺 schema 没有提供的执行时间、通知渠道或收件人设置。
4. 使用 `update_personal_mcp_brief`，仅提交当前 schema 接受的完整配置参数；服务附加字段继续保存在原始配置中。类型保持 `PERSONAL_MCP`，周期保持 `week`；提交前检查每个必填字段和修改范围。
5. 更新成功后再次读取完整配置，逐项比较本次修改和应保留内容。差异未核实前不宣称修改完成。
   - 用户要求继续或暂停定期跟踪时，调用[每周定时任务模块的维护步骤](schedule.md#步骤三维护已有任务)，同步处理对应宿主任务并读取实际状态。
6. 用户同时要求报告时，携带最新配置进入[周期简报](report.md)，默认生成月报；单次报告周期写入 `report_request` 与 `target.json`，监控的周计划保持当前设置。配置修改后已有结果对应的显示配置不一致时，记录具体差异；重新生成条件按报告模块处理。

### 步骤三：删除

1. 唯一定位目标，说明实际名称、ID、类型及删除对历史期次、运行任务和恢复能力的已知影响。未知影响明确说明未知。
2. 按 `delete_mcp_brief` 的要求取得本次删除的即时确认。其他依赖该监控的已授权操作在删除前完成。
3. 按[定时任务维护步骤](schedule.md#步骤三维护已有任务)暂停或删除已定位的对应宿主任务，保存实际结果；提交一次监控删除请求，成功后重新查询对应类型列表，确认目标 ID 不存在。

## 输出与完成条件

- 查询交付实际列表或配置说明；修改交付变更结果及读取核实结果；删除交付删除响应及列表核实结果。
- 原始参数、响应及操作位置保存在执行目录。调用失败或结果未知时保留状态，按公共规则继续核实。
