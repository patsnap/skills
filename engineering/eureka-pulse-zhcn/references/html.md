# HTML 生成

## 目标、输入与资源要求

- **目标**：将完整配置和服务端已有周期内容自动整理为独立阅读页面。
- **输入**：`report-inputs.json` 与 HTML 输出路径。输入清单引用完整配置原始响应、完整目标期原始响应及 `target.json`，包含各文件的绝对路径和 SHA-256。兼容独立传入配置、数据、目标文件，允许标准 MCP 响应、业务响应或已解开封装的业务对象。
- **重点审核输入**：依据已有资料组织本期重点时，输入清单额外引用独立的 `focus.json` 与 `focus-review.json`。审核方法和字段结构由[重点规则模块](focus.md)管理；原始配置和周期响应不修改。
- **动态统计输入**：月报和已有简报的周报在历史模块完成查询后增加 `charts`，引用[独立图表模块](charts.md)输出的 `charts.json`；仅有完整目标期资料时，同样通过图表模块及本地选择文件准备当期统计。统计和来源核验由独立模块管理，卡片选择、图表选择及绘制由 `assets/charts.js` 完成，样式由 `assets/charts.css` 管理。目标月或目标周缺失时可仅传配置、目标及图表，生成明确说明状态的历史报告。
- **内置资源**：基础样式由 `assets/report-base.css` 管理，报告模板、布局和交互分别由 `assets/report.html`、`assets/report.css`、`assets/report.js` 与 `assets/record-filter.js` 管理。生成入口通过 `common.report_assets` 检查并读取当前 Skill 目录中的资源，缺少必需文件时立即停止并报告文件名。
- **模板复用**：Python 使用 `Template.substitute` 填充内置模板，必需变量缺失时立即失败。基础样式、主题、报告样式与脚本全部内置到最终 HTML，完整安装本 Skill 后可以直接生成报告。
- **报告主题**：调用[报告配色模块](themes.md)确定所选色系，默认采用科技蓝。名称与路径由 `scripts/report_themes.py` 统一管理。生成时依次内置基础样式、所选报告主题和 `assets/report.css`，标题、标签、链接、引用、按钮、抽屉、枚举信息卡片与图表共用主题变量；语义颜色使用基础样式中的状态色。图表脚本读取主题中的系列色、文字色与边框色，配色文件缺少必要变量时直接报错。
- **检查方式**：每次生成由内置 Python 入口完成页面结构、功能节点、锚点与引用目标、卡片内容、资料覆盖及来源 SHA-256 检查。报告固定使用浅色显示，保留打印操作。样式、排版及浏览器交互检查在修改模板、CSS 或 JavaScript 时执行；遵守当前用户对视觉功能的限制，禁止视觉功能时使用浏览器 DOM、计算样式、布局和交互检查，交付时如实说明检查范围。

## 执行步骤

### 步骤一：检查资料

1. 检查真实 `pulse_id`、目标日期、`period_type` 和 `period`，拒绝运行中、失败或不完整资料。
2. 使用 `monitor.py prepare-report --config <配置原始响应> --data <周期原始响应> --target <target.json> --charts <charts.json> --output <report-inputs.json>` 完成输入检查；图表输入包含已完成的本地维度选择。完整配置必须包含真实 `pulse_id`、`detail_module` 和 `card_fields`；缺少时取得 `get_mcp_brief_info` 的完整响应。
3. 比较周期数据 `basic_info.template_custom` 中已有的 `detail_module`、`typical_filters` 和 `card_fields` 与当前配置。无 `operator` 且包含 `filter_key` 与 `value` 的成员过滤按 `in` 理解，在内存中比较其含义。服务有配置版本或更新时间时核对；未返回时保留其缺失状态，不编造版本。真实显示配置不一致时，交回报告模块核实来源与版本；原始响应始终保持原样。
   - **解析重点字段引用**：`typical_filters[].ai_fields` 是字段名数组，由公共方法 `common.resolve_ai_fields` 按 `field_key` 读取全局 `ai_fields` 定义；中文名称、数据格式、枚举和提取要求使用全局定义。渲染和展示检查共用该方法，全部配置规则均检查引用，即使本期没有入选记录也执行。引用无效时立即报错，解析结果只在内存中使用。
4. 以稳定记录 ID 建立索引；完全一致的重复记录合并，不同内容共用 ID 时立即报错。新闻分页存在后续页时停止；取得完整分页后再生成。
   - 历史会话仅保留完整任务响应时，入口可以读取其中明确为 `FINISHED` 的 `data`，继续核对身份、日期及完整性。新任务按照报告模块读取 `get_mcp_brief_data`；保留来源响应的实际结构与任务状态。

### 步骤二：自动生成

```bash
python scripts/render_report.py --inputs <report-inputs.json> --output-dir <交付目录>
```

- **色系参数**：按配色模块的选择结果传入 `--theme <中文名称或英文标识>`；省略时保持当前默认色系。指定色系并使用自动命名时，文件名增加色系名称，检查文件保存 `theme` 及配色来源。多个配色版本使用同一份输入清单分别生成。

- **文件命名与交付**：程序使用“报告主题_开始日期至结束日期_报告类型.html”命名，默认月报例如 `华为手机产品动态_2026-10-01至2026-10-31_情报月报.html`，明确要求周报时例如 `华为手机产品动态_2026-11-08至2026-11-14_情报周报.html`。默认主题采用配置中的 `pulse_name`；AI 可以根据本次明确研究对象传入 `--report-name <简洁主题>`。历史比较报告采用完整历史窗口的起止日期，类型为“历史情报比较报告”。程序处理文件名中的非法字符及长度，检查文件采用相同名称的 `.checks.json`。用户指定完整文件名时可以使用 `--output <有意义的文件名.html>`；交付使用脚本实际返回的绝对路径。

- **章节顺序**：主题与周期、统计卡片、已有 Summary、近期变化、已有文字 Insight、已有建议行动、新闻动态、重点技术动态、高相关技术、补充专利线索。有内容才生成正文章节；统计卡片采用独立网格，不增加正文章节编号。
- **顶部统计卡片**：由[顶部统计卡片模块](overview-metrics.md)计算目标期指标，依次保留“重点解读”和“高相关技术”，继续选择真实主体与分类等指标，目标四至五张、最多五张，沿用固定宽度样式。没有实际解读值的字段省略，部分解读保存覆盖数量，有效指标不足时保留已有数量。资料条数卡片直接显示来源资料；主体和分类数量卡片先显示项目，再进入对应资料列表。只有历史资料时保持本期数量未知。
- **分析图表排列**：由[图表维度选择模块](chart-selection.md)生成的选择结果决定展示维度。公司趋势与一个重要分类趋势先展示，桌面一行两个，手机纵向排列；下方显示公司与技术路线、产品线或其他有效技术分类的交叉气泡图。没有时间轴时直接汇总统计范围内全部有效资料，跨期按稳定身份去重，说明统计范围并提供包含真实来源期次的资料抽屉。Python 报告入口继续核验全部来源及本地选择文件，不生成额外趋势图。
- **动态统计章节**：Python 生成报告正文和统计数据容器，并内置 ECharts 及独立展示脚本。浏览器根据实际有效项目数量选择卡片或图表，不固定展示张数。公司维度区分专利申请人、论文机构和新闻涉及公司；方向维度使用配置与 `extracted_fields` 中已有分类。单期有一个至三个有效项目时使用 Summary 前的白色统计卡片，主题强调色大数字在上、标签在下居中排列；点击卡片通过来源弹窗查看资料。单期有四个及以上项目时采用条形图，图表留在 Summary 后的统计章节；至少两个有效历史期次统一使用多系列折线图，每个公司或分类对应一条曲线。单期结果使用“本期情报分布”，历史结果使用对应章节名称。仅有当期统计卡片时，省略空统计章节与对应导航；历史缺失期次与任务执行状态保存在统计与检查文件中，报告正文省略相应清单及执行提示。缺失与未知不计为零，点击图表继续查看真实来源记录。
- **报告版式**：页面采用主题浅色背景，正文各章节使用独立白色面板，具有浅灰边框、8px 圆角和轻量阴影。封面采用“封面统计区域”定义的渐变、白色大标题、期次、日期和关注范围说明报告主题，资料数量统一放在 header 的统计卡片区域。章节标题以左侧主题强调色标识、小字号编号和深色标题组织，分组数量与说明使用辅助文字层级；重点资料按标题、判断、解读与证据图片形成连续文章。长文本配置字段在全部屏幕宽度中均采用名称在上、正文在下的排列，正文与名称左侧一致，正文列表保留项目符并取消额外左侧缩进；enum 分类字段采用“分类字段排列”定义的信息块。相关度与专利号、公司、日期集中显示在标题下方的信息行，重点序号单独显示。横向章节导航显示当前章节和实际数量，子目录可展开，页面顶部显示随阅读位置变化的进度条。概述全文及来源直接显示，首段与后续内容按阅读层级排列。交互状态使用简短过渡，遵守减少动态效果设置，打印封面使用白底深色文字，并隐藏阅读进度。
- **正文色彩层级**：复用设计 Token 与报告主题，章节编号使用辅助文字色，章节标题使用主题深色文字；编号与标题间隔保持 12px，标题区左侧保留 4px 主题强调色标识。概述首段与后续全文在白色章节面板中直接显示，通过字号及段落间距区分层级。重点资料的 `display_summary`、专项解读和普通资料正文均采用常规字段排列，直接显示字段名称和内容，正文使用 14px 字号及 24px 行距；字段名采用主题深色文字与随文字宽度变化的主题浅色背景。桌面、手机与打印保持相同的字段结构和完整文字。打印保留分组标题的配色，色彩不表示相关度或效果等级。统计面板由[独立图表模块](charts.md)维护，图表面板和滚动区域采用透明背景与主题深色标题。
- **序号与正文位置**：章节序号和重点条目序号按实际文字宽度排列，与后方标题间隔 12px。概述、分组容器和图表使用章节内容的左侧起点；专利卡片内的序号、来源信息与解读正文使用相同的左侧起点，并与卡片边框保持内边距。重点条目只在标题首行保留序号列，后续内容使用卡片内部的完整正文宽度；桌面、手机和打印采用相同的位置关系。
- **字体与阅读字号**：普通文字使用 `BlinkMacSystemFont,Roboto,Helvetica Neue,Arial,PingFang SC,Microsoft YaHei,微软雅黑,sans-serif` 字体顺序。正文、重点摘要、技术解读、配置字段值及抽屉正文使用 14px 字号与 24px 行距，内容字段名称使用 14px 与 20px 行距，来源与图片说明等辅助信息使用 12px。概述首段使用 16px，资料标题使用 16–22px，章节标题使用 20px，封面标题使用 28–32px。手机保留正文字号，通过换行及单列排版适应宽度。
- **目录筛选**：高相关技术章节由独立的 `assets/record-filter.js` 管理目录筛选。目录按钮使用配置目录名称、原始目录身份和完整数量，空目录禁用。每个目录默认展示前两条、每次追加最多五条，数量按真实资料身份去重；点击“全部”恢复全部目录。正文锚点可以恢复筛选并显示对应资料，引用继续直接打开抽屉；打印完整显示全部目录与资料，打印后恢复筛选及展开状态。完整性检查始终覆盖全部资料。
- **独立新闻章节**：从原始新闻、技术资料及重点结果中收集实际新闻，按稳定身份去重，在技术章节之前独立展示“新闻动态”；没有新闻时省略章节。迁移展示时保留原始标题、全部配置字段、已有重点解读、来源链接与详情，不在技术目录中重复展示新闻。检查直接比较原始新闻集合与该章节记录集合。
- **分组导语**：“重点解读”和“高相关技术”下的正文子目录标题统一采用主题浅色背景、左侧 4px 主题强调色标识、上下 8px 与左右 12px 内边距；标题使用主题深色文字、16px 字号、24px 行距和 600 字重。分组容器从章节内容的左侧起点开始，与专利卡片外边缘保持一致。数量在标题同一行显示为“1条”“2条”等真实总数，采用辅助文字颜色、14px 字号、24px 行距和 400 字重，无独立背景、边框及内边距。说明正文使用 14px 与 24px 行距。导语与后续资料保留 24px 间距，屏幕和打印采用相同层级。
- **子目录分批显示**：“重点技术动态”“高相关技术”及“补充专利线索”的各资料分组默认显示前两条，超过两条时提供居中的无边框文字按钮“查看更多”，按钮与上方最后一条已展示资料的边框间距为 8px。该条资料在入口可见期间取消底部外边距，其他资料之间保持原有间距；追加资料后，间距规则继续作用于新的末条已展示资料。按钮保留鼠标悬停、按下和键盘焦点状态，每次追加最多五条，全部显示后隐藏该入口。各分组独立管理数量，标题及菜单数量始终表示该分组的完整资料总数。全部记录仍保存在 HTML 中，完整性检查覆盖全部记录；检查文件分别记录完整记录数与初始显示数量。引用可以直接打开尚未展开记录的抽屉，正文锚点定位时显示对应资料。打印显示全部记录并隐藏“查看更多”，打印后恢复各分组原来的展开数量。原始 MCP 响应保持不变。
- **封面顶部与高度**：Eureka、报告期次和打印入口合并到封面顶部同一行，左侧显示品牌与期次，右侧显示打印入口；章节导航滚动时固定在页面顶部。封面采用单列紧凑排版，桌面顶部留白 24px，平板与手机顶部留白 20px。标题、日期和关注范围完整显示，使用自然高度适应长内容。
- **已有文字**：Summary 读取 `overview.overall_judgement` 或明确的 `summary`；Insight 仅读取结果中的完整文字，按配置顺序组织；建议只读取结果中的明确建议。配置中的分析要求不作为报告成稿。
- **重点技术动态**：严格匹配 `typical_filters[].name`、资料类型和非空 `typical_result`，按配置顺序和 key 生成目录。每行显示一条专利或论文，标题使用 `ai_title`；正文直接显示 `display_summary` 与 `extracted_content`，分别使用 `display_summary_field_name` 与 `extract_content_field_name` 作为字段名称。其他业务字段按照对应 `typical_filters[].card_fields` 的顺序直接展示非空值，并显示字段名称。可选 key 缺失时根据名称生成稳定的页面锚点；不改变配置和分组业务含义。候选标签不直接决定展示。
- **本期资料审核重点**：独立审核文件引用原始记录键及规则，不改变服务端重点对象。脚本核实业务对象与文件校验值、全部高相关资料审核范围、资料类型和至少两个不同原始字段证据，在重点章节展示入选依据及原文摘录，并说明来源为本期资料复核。没有入选资料时显示审核原因。
- **高相关技术子菜单**：正文标题与顶部导航统一使用“高相关技术”。`detail_module.mode=split` 时，严格使用 `sub_modules` 中的名称、顺序、`data_scope` 和过滤条件组织子菜单与正文。即使原始 `visible=false`，高相关资料仍按这些目录分类；无记录的配置项在原位置显示数量零并禁用。未匹配目录的高相关记录追加到未分类区域，保留原始分类缺失状态。`merged` 使用整体分组；模式为 `none` 或没有可用目录时，仍以“高相关技术资料”保留全部尚未显示的高相关记录。全部高相关完整性检查始终执行，服务配置与原始响应保持原样。
- **字段过滤**：同组条件使用 AND。脚本支持 `eq`、`ne`、`in`、`not_in`、`contains`、`contains_any`、`contains_all`、`gt`、`gte`、`lt`、`lte`、`exists`。多值的集合操作在脚本中统一定义，未知操作符立即报错。包含 `filter_key` 和 `value`、缺少 `operator` 的过滤按成员匹配处理，包括公司和 AI 分类字段；全部处理仅发生在内存中。
  - `eq`、`in`、`contains_any`：实际值与候选值至少一项相等；`ne`、`not_in`：没有相等项；`contains_all`：全部候选值属于实际值集合。
  - `contains`：字符串按子串匹配，数组按成员相等匹配；数值操作符比较单个数值；`exists` 检查是否有值。字段缺失时其他条件不成立。
- **相关性**：专利和论文优先显示 `score >= 4`；没有任何高相关技术时按配置展示已有低相关技术并提示。存在高相关技术时，低相关专利可以进入补充线索，低相关论文不进入正文。
- **卡片标题与来源**：在标题文字前显示“专利”“论文”或“新闻”类型标签，与标题首行处于同一行；重点、普通和补充资料统一显示。类型来自原始记录，标签使用白底、主题浅色描边、主题深色文字、12px 字号和 4px 圆角。长标题自然换行，标签保持完整，第二行及后续内容从类型标签的左侧起点开始。始终显示来源中已有的可识别标题和基础身份，包括可用的专利号、DOI、公司、公开日期、来源链接与相关度。标题依次读取重点结果的 `ai_title`、标准标题、`technical_title`、专利号、DOI、稳定资料 ID。专利抽屉和数量卡片的来源列表读取标题文字，资料类型独立管理。来源信息集中排列在标题下方，分类字段采用对应的信息块；必需身份没有其他可用字段时显示稳定资料 ID。
- **新闻信息与详情**：公司和已有日期使用辅助文字排列在标题下方，相关度使用紧凑的中性色标签；“阅读原文”位于信息行右侧，窄屏时自然换行。详情入口使用“查看详情”和“收起详情”，文字后显示方向箭头，支持键盘展开及收起。保留完整详情字段与来源，信息行和入口采用紧凑间距，打印时直接显示完整内容。
- **高相关技术正文**：专利与论文默认展示 `technical_title`，没有值时展示原始摘要；两者均为空时省略正文区域。其他字段按照整体 `card_fields` 中对应资料类型的顺序直接展示非空值，并显示字段名称。已经作为默认正文显示的字段不重复生成。标准字段读取原始资料，AI 字段读取 `extracted_fields`；新闻按其配置字段展示。
- **解读内容层级**：两个重点特殊字段、默认正文、情报研判和配置字段分别组织，保留字段名称及完整文字。普通记录的长默认正文在屏幕中显示阅读预览，详情显示全文；情报研判与配置字段在卡片正文可直接阅读。原始标题、原始摘要与审核证据完整保留在详情中。原始摘要中的 HTML 标记使用已有解析库转换为可读文字，来源文件保持原样。
- **内容字段分区**：专利、论文和新闻的特殊字段、默认正文以及详情字段，名称使用主题深色、14px 字号、20px 行距与 600 字重。字段名采用随文字长度变化的主题浅色背景，上下留白 4px、左右留白 8px、圆角 4px，最大宽度为当前内容区域，长名称自然换行。字段名称独占一行，与下方正文间距 8px，字段模块之间间距 24px；背景容器与正文保持相同的左侧起点。配置字段采用下方“分类字段排列”定义的信息块，情报研判使用对应独立样式。报告正文、详情展开区域、专利抽屉、手机和打印使用相同规则；打印时字段名称与后续内容保持连续。专利号、公司、日期、相关度和来源链接沿用标题下方的信息行样式。
- **分类字段排列**：Python 根据已解析字段定义中的 `data_format=enum` 标记 `field-enum`。正文和抽屉中的 enum 及 `record-tags` 字段采用并列的主题浅色信息块，8px 圆角、16px 内边距、12px 块间距，同一行高度一致。字段名称在上，使用主题深色、12px 字号和 400 字重；字段值在下，使用主文字色、14px 字号与 24px 行距，名称和值间距 8px。各字段沿用配置顺序，根据容器宽度排列，手机采用单列、12px × 16px 内边距。多值以顿号分隔并允许换行。文本型字段独占完整一行，直接显示字段名称和全部段落与列表。字段名称、原始值、顺序及完整内容保持不变。
- **情报研判**：将原始记录中的 `analysis` 放在每条资料的最后一行，位于正文、配置字段及详情内容之后，字段名称统一为“情报研判”。使用顶部浅色虚线、辅助文字色与 14px 正文，名称与首段同行，长内容自然换行，已有内容完整显示，字段为空时省略。正文、抽屉及打印共用相同内容，配置字段已包含 `analysis` 时保持一次展示；不生成或改写原始研判内容。
- **封面统计区域**：封面效果以及统计卡片的背景、边框和文字颜色由[报告配色模块](themes.md)按所选主题统一管理。顶部统计卡片放入 `header.report-cover`，位于标题、日期与范围说明下方，卡片来源索引与点击操作继续保留。沿用固定宽度，桌面高度 88px，手机每行两张、高度 80px；hover、按下与键盘焦点使用相应状态。打印使用白底、主题深色数字和灰色名称。正文从 Summary 直接开始，保留每项真实指标及其数量。
- **字段显示顺序**：enum/tag 信息卡片位于专利号、公司、日期等来源信息下方，处于正文开头，使用卡片完整宽度。重点摘要、专项解读、默认技术正文及文本型配置字段依次组织在后方；分类组与文本组内部各自保留配置顺序，情报研判保持在资料末尾。抽屉与打印使用相同的分类位置，完整性检查同时覆盖分类组与文本组。
- **标准字段名称**：`technical_title` 的显示名称使用“AI 核心要求”，由 `scripts/render_report.py` 的 `LABELS` 统一维护；字段键和原始内容保持原样。
- **字段列表排版**：配置字段中的项目符与首行正文在同一行显示。列表项首段采用行内显示，后续段落保持段落结构与间距；多行正文沿用字段内容的左侧起点，嵌套列表保留层级。正文、专利抽屉及打印使用相同规则，原始资料与段落标签完整保留。
- **重点与补充资料**：重点在各屏幕宽度均采用单列，每条专利或论文独占一行；正文在左、附图在右，窄屏将附图置于正文下方。阅读标题来自独立审核记录时，保留已有入选依据、原始标题和原文证据。特殊字段、配置字段及图片仅展示实际返回且可用的内容；空值直接省略相应区域、字段名称和提示文字。论文与新闻采用连续条目，补充专利采用内边距较小的卡片与小幅附图；附图直接显示并可打开原图。论文与新闻详情可以展开阅读，打印时同时显示概述与全部资料详情。
- **专利资料边界**：重点、高相关和补充专利均采用独立的白底卡片，使用 1px 浅灰边框与 8px 圆角。桌面卡片之间留白 24px，重点与普通卡片内边距 24px，补充卡片 20px；手机卡片之间留白 20px，内边距统一为 16px。首条、末条及追加显示的资料采用相同边界与内边距。鼠标悬停时边框使用主题浅色并显示轻量阴影，点击与键盘入口继续打开对应资料抽屉。资料类型标签采用白底、主题浅色描边与主题深色文字，使用 12px 字号和 4px 圆角。打印保留边框，卡片间距与内边距均为 16px，完整显示资料，并允许长内容跨页。
- **资料详情抽屉**：专利卡片、可操作的专利标题及正文引用共用一个右侧原生 `dialog`。专利标题保留原有文字排版，使用原生按钮支持 Tab 进入、Enter 或空格打开抽屉及可见焦点，卡片正文点击也可打开对应专利。引用可以打开对应专利、论文或新闻，抽屉标题区使用主题浅色背景，正文依次显示身份与来源信息、已有附图、分类与完整解读、全部详情字段、已有原始摘要及证据。附图位于标题和资料信息下方的独立一行，多张已选附图按可用宽度排列。原文和图片链接继续直接打开相应来源。抽屉正文独立滚动，窄屏使用完整宽度；支持按钮关闭、遮罩关闭、Escape、键盘进入和焦点恢复。抽屉内继续打开其他引用时切换到对应资料，关闭后将焦点恢复至最初的打开入口。打开期间限制背景滚动。详情在卡片与抽屉之间移动，保留同一份内容及稳定记录键；打印前将详情放回各自卡片，完整显示全部记录及标题，打印后恢复阅读状态。论文与新闻已有的正文展开入口继续保留。
- **图片大图预览**：报告正文与详情抽屉中的图片支持鼠标悬停显示浮动大图，图片链接获得键盘焦点时也显示相同预览。预览使用原始图片地址，按比例完整显示，宽度最多 640px、高度最多 480px，四周保留至少 16px 屏幕空间。抽屉内的预览保存在当前 `dialog` 内；鼠标移开、键盘焦点离开、图片所属区域滚动、调整窗口、切换资料、关闭抽屉或打印时隐藏预览。抽屉图片预览期间，背景页面的滚动保持当前预览。预览不接收鼠标点击，原有点击图片打开原图的操作继续有效；图片未加载成功时保留原有状态。
- **正文引用**：将 `page://detail-<id>`、`page://typical-<id>` 及其中带成对花括号或 URL 编码的 ID，在内存中解析为本页真实资料的引用。概述以外的引用保留原编号，各自显示为主题强调色方括号上标，例如 `[1]`、`[2]`，使用 12px 字号与独立间距，长串引用可以换行。鼠标悬停显示资料标题，键盘 Enter 或空格以及点击均打开对应资料抽屉，保持正文阅读位置。原编号、顺序及原始响应保持不变。无法唯一定位时保留独立引用样式、说明暂不可定位，并在检查文件记录原引用，禁止拼接裸数字或生成无目标链接。
  - **概述数量入口**：由 `scripts/citations.py` 在内部 ID 转换完成后组织引用。概述同一父节点中连续出现、仅以空白或引用分隔符隔开的引用，合并为一个主题强调色方括号上标；遇到业务文字、句号或段落边界时分别保留。数字表示本处按稳定资料身份去重后的技术资料条数，例如 `[21]` 表示 21 条；单条资料显示 `[1]`。原引用编号、重复出现次数、原顺序与内部 ID 保存在该入口的隐藏成员中，完整性检查继续读取这些真实成员，原始响应保持原样。
  - **概述引用列表**：点击数量上标或使用键盘 Enter、空格，在现有右侧抽屉中显示本处的去重资料列表，按首次出现顺序组织。专利引用显示“专利列表”，其他类型使用真实资料类型名称，混合类型使用“资料列表”；列表包含真实标题、类型、专利号或 DOI、公司和已有公开日期。专利条目在基础信息下方显示 `technical_title`，缺失或仅含空白时显示 `abstract`，两者均为空时省略正文；使用 14px 字号与 24px 行距，保留完整文字和已有段落。Python 从原始记录按此顺序准备独立的列表正文模板，浏览器直接读取；列表正文不受卡片 `card_fields` 显示配置限制，字段名称及原始响应保持原样。点击条目继续查看完整资料，支持“返回专利列表”或相应类型的返回入口，保留列表滚动位置与条目焦点；关闭抽屉后恢复数量入口的焦点及概述阅读位置。引用可以列出正文尚未展开的真实资料，正文的展开数量保持原有状态。打印保留数量入口及全部资料详情。
  - **引用列表条目边界**：列表模式使用浅灰色抽屉正文背景，每条专利、论文或新闻使用独立白底卡片，采用 1px 浅灰边框、8px 圆角和设计系统的卡片阴影。卡片之间间距 16px，桌面内边距 20px，手机内边距 16px；首条和末条保留完整边框与相同内边距。类型和标题、基础信息与已有列表正文保存在同一卡片中；基础信息使用紧凑排列。进入完整详情时，抽屉正文恢复白底；返回列表时保留卡片、原滚动位置和条目焦点。
  - **概述内部 ID**：`scripts/citations.py` 负责引用节点、概述内部 ID 转换及相应检查；`render_report.py` 传入全部原始资料的身份索引与实际抽屉位置。在概述普通正文中识别完整 UUID，以及与真实 UUID 前八位相同的短 ID，按资料类型与完整身份唯一定位。编号优先沿用概述中同一资料已有的引用编号；没有编号时，从已有最大数字编号之后依次分配。仅包含这些 ID 与分隔符的圆括号整体转换为相邻上标引用，保留其他业务文字、Markdown 结构和原有引用。完整 ID 没有对应资料、短 ID 对应多条资料或目标没有抽屉时立即停止生成，报告具体 ID；不根据未知短字符串猜测资料。转换只作用于内存中的 HTML，来源响应保持原样。
  - **概述引用检查**：从原始概述独立统计需要转换的 ID，逐处比较生成引用的数量与身份，核实抽屉资料、已有编号和普通正文中没有残留已识别 ID。继续核对原始引用身份、编号与出现次数，每组去重后的成员顺序、数量标记及对应列表目标，同一位置只保留一个入口。检查文件保存 `summary_internal_ids_checked`、`summary_internal_id_records`、`unconverted_summary_internal_ids`、`summary_citation_groups` 和 `summary_citation_members`；检查通过后继续资料覆盖、设计与浏览器检查。
- **重点图片**：按照 `important_figures` 的选择顺序显示前三张图片，保留图号、说明和证据来源。存在直接图片地址时使用该地址；仅返回 `figure_no` 时，通过原始 `pdf_images[].fig_title_code` 或 `labels` 匹配图片地址。同一图号对应多个不同地址时停止生成并说明歧义。已选图号没有匹配地址时省略该图片，在检查文件保留未匹配图号；实际选择少于三张时展示已有选择。没有可用选择结果时，已有普通资料附图继续作为资料图片展示。
- **普通图片**：依次选择 `important_figures`、`patent_image`、`pdf_images[0]` 中可用的图片。桌面正文右侧直接显示，窄屏在正文下方显示；加载失败显示提示，图片说明继续保留。
- **安全**：Markdown 使用第三方解析器且关闭原始 HTML；链接与图片通过协议及地址检查。正文引用按本模块的引用规则绑定本页资料，其他来源链接保留安全的 HTTP 或 HTTPS 地址。

### 步骤三：检查与交付

1. **生成时检查**：脚本检查文档根节点、标题、正文与抽屉等功能节点、唯一锚点、内部链接和每张卡片的可识别标题与有效文字，直接从原始记录建立全部高相关记录集合，独立比较最终 HTML 中的记录键；任何显示开关、目录模式或过滤条件均不能跳过检查。继续核实重点两个特殊字段及名称、三张已选图片与原始图号的对应关系、重点及普通配置字段、全局字段名称、枚举标签与值、默认技术标题或摘要、重点证据、引用编号及抽屉目标、全部类型的抽屉内容、目录数量和独立文件结构。对应 `.checks.json` 保存 `page_structure_checked`、内置基础样式的 `base_styles` 路径及 SHA-256、原始路径与 SHA-256、高相关总数、已显示总数、缺失记录键、服务端重点数量、本期资料审核重点数量、引用检查数量与无法定位的引用。输出路径不得覆盖任何输入，渲染前后核对来源及基础样式校验值。执行命令检查 Python 的退出状态并保留完整输出；使用管道时启用 `pipefail`，失败时停止依赖步骤。
2. **维护时检查**：修改模板、CSS 或 JavaScript 时，使用实际浏览器检查文档宽度、报告标题与章节层级、目录定位与当前章节状态、图片布局、引用上标与换行、点击引用后资料身份与内容、专利及论文与新闻的抽屉打开和关闭、抽屉内引用切换、阅读位置与焦点恢复、完整详情、论文与新闻的展开及收起、表格滚动、键盘访问和打印时的完整内容。覆盖桌面、窄屏、两种系统外观设置下的固定浅色配色，以及抽屉打开和关闭时的打印。常规报告复用已经验证的模板，用户要求页面审阅或出现显示问题时再执行相应浏览器检查。原始图片 URL 可用性单独记录；网络加载失败不改变内容事实。
3. 检查通过后交付 HTML 文件。明确请求完整离线图片时，需要另外取得图片并嵌入；默认单文件内置 CSS 和 JavaScript，原始图片保留服务 URL。

## 输出与完成条件

- 返回 HTML 和检查文件的绝对路径，交回当前调用模块完成文件交付。
- 仅使用本次有效资料；Python HTML 生成脚本不调用远程业务服务，不生成评分或新的研究结论。数量由独立统计程序计算并保留来源记录，浏览器展示由独立 JavaScript 模块完成。
