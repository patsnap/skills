# 报告配色

## 目标与输入

- **目标**：根据用户指定的名称生成整页配色一致的公司或技术报告，支持同一份内容输出多个色系版本。
- **输入**：用户的色系要求、已有报告的 `.checks.json`（如有），以及 HTML 模块准备的报告输入清单与交付目录。
- **公共入口**：`scripts/report_themes.py` 统一管理五套色系的名称、别名、默认值和配色文件路径。默认科技蓝为 `blue`，每套色系读取 `assets/themes/<英文标识>.css` 及共享样式。
- **配色与封面**：五套配色通过 `assets/themes/reference-report.css` 统一映射到报告变量，主色、深色、浅色、页面与枚举背景、边框及封面颜色分别由各色系文件管理。封面采用 140° 三段渐变及右上方圆形光晕；科技蓝以 `#00369C` 为基调，通过 `#053DA5`、`#0D4AB4` 形成同色轻微渐变，光晕使用 14% 透明度的浅蓝。统计卡片使用透明浅色背景与白色数字；共享文件一并内置。字体、正文结构、资料与交互沿用当前报告。

## 内置色系

| 名称 | 英文标识 | 适用报告 |
|---|---|---|
| 华为红 | `red` | 公司技术简报、重点进展 |
| 科技蓝 | `blue` | 技术研究、公司情报 |
| 生态绿 | `green` | 产业生态、长期跟踪 |
| 砚紫 | `violet` | 专题研究、个人阅读 |
| 石墨金 | `amber` | 公司布局、管理层阅读 |

## 执行步骤

### 步骤一：确定报告色系

1. **采用用户选择**：用户给出上述名称、英文标识或已有别名时直接采用；完整名称和别名由程序解析。运行 `python scripts/report_themes.py` 可取得色系目录与全部可用名称。未知名称立即报错，保留用户要求供确认。
2. **确定默认与已有配色**：用户未指定色系时采用科技蓝 `blue`；明确要求沿用已有报告的配色时，读取其检查文件中的 `theme.id`，核对属于上述五套色系后传入生成参数，没有配色记录时使用科技蓝。无法识别的名称按本步骤第一项处理。报告输入、监控配置和 MCP 意图保持各自原有用途，配色只作为本地生成参数。
3. **组织多个版本**：用户要求多个色系时，保留其顺序，按解析后的英文标识去重。每个版本复用同一份报告输入、目标期、审核与统计文件。

### 步骤二：生成对应报告

1. **传入色系参数**：将选择结果交给 HTML 生成入口，使用 `--theme <中文名称或英文标识>`。例如：

   ```bash
   python scripts/render_report.py --inputs <report-inputs.json> --output-dir <交付目录> --theme 科技蓝
   ```

2. **生成独立文件**：指定 `--theme` 并使用 `--output-dir` 时，程序在有意义的报告文件名后附加色系名称，例如 `华为手机产品动态_2026-10-01至2026-10-31_情报月报_科技蓝.html`；使用 `--output` 时采用用户指定的完整路径。多个版本分别生成，不覆盖既有版本。省略色系参数时，默认配色和原有文件命名继续有效。
3. **统一页面配色**：程序依次内置 `assets/report-base.css`、所选主题和共享报告样式。五套配色使用本模块定义的共同封面样式。正文强调色、标签、枚举卡片、引用、按钮、抽屉与图表读取同一套主题变量。语义状态使用内置基础样式中的状态色，图表保留标签、符号和数值。配色不会改变资料、结论、统计维度、数量及引用目标。

### 步骤三：检查并交付

1. **执行生成检查**：由 HTML 模块执行资料覆盖、引用目标、页面结构与来源校验；每个版本的 `.checks.json` 增加 `theme`，保存英文标识、显示名称和所用 CSS 文件的绝对路径及 SHA-256，存在共享配色文件时同时记录 `shared_source`。未知色系或缺少配色文件时立即停止生成。
2. **核对版本一致性**：多版本的原始来源引用、正文记录集合、统计数据和引用目标一致，仅主题样式与输出文件路径不同。对照来源 SHA-256 确认原始 MCP 响应保持原样。
3. **交回报告模块**：返回各色系实际生成的 HTML 与检查文件路径，按 HTML 模块的生成检查结果交付。维护模板、CSS 或 JavaScript 时执行对应的样式与交互检查；交付时如实说明已经完成的检查范围。
