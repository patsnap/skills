# 动态统计展示

## 目标、输入与职责

- **目标**：根据用户的监控目的及实际返回的有效维度，选择卡片、分布图、多系列时间折线图或公司与技术方向气泡图，帮助读者快速了解资料分布及需要阅读的内容。页面按有效数据确定展示数量。
- **输入**：已有历史使用[历史模块](history.md)输出的 `statistics.json`；仅有当期时使用完整配置原始响应、完整目标期原始响应及 `target.json`。
- **生成职责**：`scripts/charts.py` 负责统计数据与来源核验，Python 报告程序继续生成整体 HTML。`assets/charts.js` 独立负责浏览器中的维度选择、组件选择、图表绘制和交互，`assets/charts.css` 管理样式；ECharts 随报告内置。
- **展示要求**：按 [HTML 模块](html.md)使用内置基础样式及所选主题中的系列色与字号，保留数据标签及可访问性要求，继承用户指定字体和报告固定浅色。图片及原始资料链接沿用原有规则。

## 执行步骤

### 步骤一：确定有效统计维度

1. **理解监控目的**：按[图表维度选择模块](chart-selection.md)读取监控问题、实际字段及有效资料，保存本地 `chart-selection.json`。选择一个公司趋势维度、一个最高有效 `level` 或 AI 认为最重要的分类趋势维度，以及一个按技术路线、产品线、其他技术字段顺序确定的公司交叉维度。需要明确限定统计字段时使用 `--dimension-field <field_key>`，可以重复传入。
2. **使用实际字段**：默认采用已有子目录或卡片使用的枚举 AI 字段，统计实际返回的分类值；没有实际值的候选不展示。自由文本不依据词频猜测分类。公司维度优先读取资料已有公司名称，论文机构采用实际 `organizations`；只依据明确标准名称归并，不推断母子公司关系。
3. **明确统计范围**：专利申请人、论文机构、新闻涉及公司分别统计。技术或产品分类使用高相关技术记录，显示已分类与适用记录数量；公司分布使用对应类型的完整返回记录，说明其范围。多值资料分别计入对应项目，不能把分类数量直接相加作为总量。
   - **按图表维度确定范围**：具有时间轴的图表按期次分别统计；没有时间轴的分析图表直接汇总本次统计范围内全部已经取得且定义一致的有效资料，跨期相同资料按稳定身份去重。图表说明统计范围及实际取得的资料期数，来源列表保留每条资料的真实期次。字段定义不同且无法确认含义一致时停止合并并报告实际问题。
   - **选择公司与技术方向交叉维度**：由图表维度选择模块检查真实分类字段与申请人记录的交集，按技术路线、产品线、其他技术字段的顺序选择。选择理由和本地展示设置保存在 `charts.json` 与 HTML 数据中，不修改服务端配置；程序不固定要求某个字段键或分类名称。
4. **检查历史依据**：月报查询包含目标月的最近十二个完整自然月，周报查询最近八个完整自然周，历史缺失均不补跑。每期从完整原始响应生成公司、技术或产品分类分布，同一期内按稳定记录去重。按[历史模块的比较要求](history.md#步骤三检查比较条件并统计)核对每个维度的实际定义、评分完整性及共同资料类型，至少两个有效期次时使用多系列折线图展示历史数量。监控范围、评分规则或配置版本没有返回时保留解释限制，继续展示实际时间曲线。目标期缺少完整资料或某个字段时，其他历史期次的有效维度继续参与，并标注实际来源日期。

### 步骤二：准备展示数据

- **已有历史**：

  ```bash
  python scripts/charts.py --statistics <history/statistics.json> --selection <chart-selection.json> --output <history/charts.json>
  ```

- **当期展示**：取得完整 `config`、`data` 和 `target` 后，同样使用选择文件准备图表数据，再交给 Python 报告入口；需要指定统计字段时重复提供 `--dimension-field`：

  ```bash
  python scripts/charts.py --config <配置原始响应> --data <周期原始响应> --target <target.json> --selection <chart-selection.json> --dimension-field <实际field_key> --output <charts.json>
  ```

- **来源检查**：程序从实际响应重新计算数量及记录键，检查身份、日期、分页、重复记录和 SHA-256。任何输出都不能覆盖原始配置、周期响应、目标或其他来源文件。`charts.json` 只保存派生数据和来源引用。
  - **来源列表字段**：各期 `records` 索引保留资料标题、类型、来源链接、`technical_title` 和 `abstract`。两个正文值读取对应原始标准字段，摘要中的 HTML 通过已有解析库转换为可读文字；不生成新摘要。静态来源检查重新读取原始响应并比较完整索引。更新展示字段后，从原始响应重新生成派生统计与图表文件，保留原有输入文件。
- **保存维度选择**：`--selection` 引用由 AI 保存的字段角色、重要性顺序及业务理由。程序检查真实字段、有效数据和 `level`，输出 `dimension_selection` 与选择来源；后续重新渲染继续使用同一来源。`--company-route-field` 可以用于已有明确字段的独立展示请求，与选择文件同时提供时须与选择结果一致。

### 步骤三：根据数据选择卡片或图表

- **产品线展示**：产品线维度采用图表。有同定义且可比较的历史期次时使用时间图；仅有当期或汇总资料时使用条形图，包括只有一至三个有效产品线的情况。通过真实 `field_key=product_line` 或本地维度选择中的 `role=product_line` 识别，保持实际值、数量及来源不变。其他维度继续按下面的有效数量与比较条件选择展示。

1. **顶部指标**：由[顶部统计卡片模块](overview-metrics.md)独立选择，目标四至五张、最多五张。保留“重点解读”和“高相关技术”，再选择有真实资料的主体数量、重要分类及其他有效指标。字段完全没有解读结果时省略，部分解读时保存实际覆盖数量；缺少指标时保留已有数量。顶部卡片统一使用目标期，资料条数和项目数量使用各自的真实计数单位与来源操作。
2. **少量有效项目**：一个至三个实际有数值的公司或分类在对应分析面板内使用统计卡片；顶部区域的指标数量由其独立模块管理。桌面卡片固定宽 180px、高 112px、间距 16px，从左侧横向排列并根据空间自动换行；卡片保持固定宽度。采用白色背景、较清晰的灰色边框、4px 蓝色顶部边线、8px 圆角和设计系统的卡片阴影。上方居中显示深蓝色 36px 数字，下方显示深色 14px 单行名称，数字与名称均使用 600 字重，每张卡片只保留数量和名称。手机卡片固定宽 160px、间距 12px，空间不足时换行；单张与多张采用相同宽度。打印卡片固定宽 160px、高 100px，保留边线并移除阴影。长名称使用省略号并保留完整提示；字段名称、日期、范围及分类覆盖信息保留在提示与来源内容中。点击卡片打开独立的来源弹窗，支持关闭按钮、Escape 及焦点恢复。
3. **多项数量比较**：四个及以上有效项目使用横向条形图，按实际数量排序，显示数值标签与提示，点击图形查看对应资料。长名称换行，窄屏在图表容器中滚动。
   - **图表来源抽屉**：点击条形图或多系列折线图中的有效数据点时，在右侧打开资料列表。抽屉标题显示维度、所选项目及资料数量，正文显示实际期次日期；每条资料先显示标题，再显示完整 `technical_title`，没有非空值时显示 `abstract`，两者都没有时仅显示标题。保留可用的标题链接，按该数据点的真实资料键生成列表。使用现有统计来源 `dialog`，图表来源采用右侧抽屉，统计卡片继续使用来源弹窗。桌面抽屉宽度最多 720px，手机使用完整宽度；正文独立滚动，支持关闭按钮、Escape、遮罩关闭及焦点和阅读位置恢复。打印省略抽屉，报告中的图表与资料继续完整显示。
4. **历史变化**：每个维度采用最近一期实际定义，核对全部有效历史期次；目标期没有该字段时继续使用其已有历史。至少两个同定义且可统计的期次统一生成多系列折线图，适用于专利申请人、论文机构、新闻涉及公司、技术方向、产品线及其他有效分类；每个公司或分类对应一条曲线。横轴从该维度首个有效期次到最后一个有效期次，月份保留年份和月份，周使用完整开始日期，纵轴显示整数资料数量。曲线使用实际数值、不平滑、不叠加面积，提供数值标签、不同颜色与数据点形状、按时间显示的提示，以及可滚动和可选择的图例。缺少版本或检索条件说明不阻止时间曲线；集中说明各期收录数量的解释限制，不计算增长率。中间缺失及不同定义位置保持空缺，曲线在空缺处断开。各期已分类与适用数量、共同资料类型及省略类型直接说明。某分类没有出现且该期分类覆盖不完整时保持未知。点击数据点按对应期次查看真实来源。
   - **选择与排列**：只展示选择模块确定的公司趋势和一个重要分类趋势。两张趋势图位于同一行，桌面间距 24px，窄屏纵向排列；选中的公司交叉图在下方使用完整可用宽度。分类趋势可以和交叉图使用同一字段。其他候选保留统计与来源，不重复生成额外趋势图。
5. **公司与技术方向气泡图**：使用实际指定的方向字段，标题为“公司 × 方向字段显示名称”。横轴为技术方向，纵轴为真实专利申请人，气泡面积与对应公司、方向中的高相关专利数量成正比。先按各期真实记录键求申请人成员与方向分类成员的交集，再将统计范围内全部有效期次的交集汇总，同一气泡内跨期按记录键去重。只使用原始 `score >= 4`、字段适用类型内且评分完整的专利；公司或方向缺失的资料不进入交叉统计，说明有效交叉资料与适用资料的去重数量。适用资料索引读取字段 `components.patent.eligible_members`，不能直接相加各期总数。共同申请人、多值分类或不同期次实际分类分别进入有来源支持的项目，不能将全部气泡相加作为专利总量。
   - **范围与来源**：图表直接展示统计范围内的全部有效资料，省略月份或周次选择器。横纵轴采用全部有效资料中的真实公司和方向名称，气泡面积与去重后的数量成正比。提示显示公司、方向、数量及统计范围；点击气泡打开汇总专利列表，每条专利显示实际来源期次。跨期重复资料在同一气泡内只显示一次，保留全部命中期次，列表标题与正文采用最近命中期次的原始内容。缺失期次保持未知，不计为零，不自动补跑。没有任何真实交叉资料时，该方向继续使用原有的有效分布或时间图。
6. **单期或无有效分类**：某个维度不能形成有效时间比较时，汇总统计范围内该维度的全部有效资料，按稳定身份去重，选择卡片或分布图，并说明实际统计范围；其他维度继续选择历史图。全部维度都没有有效项目时，按统计范围内已取得的资料类型生成去重数量；仍无可统计内容时仅说明范围与状态。历史缺失期次与任务执行状态保存在统计与检查文件中，报告正文省略相应清单及执行提示。仅有当期统计卡片时，省略空统计章节与对应导航。
7. **保留分析依据**：同一维度选择一种主要表达。字段缺失及未知不计为零，不生成没有资料支持的图表。数量只描述资料收录情况；技术实力、研发投入及商业进展需要另外的证据。

### 步骤四：检查并交接报告

1. **静态来源检查**：Python 入口重新计算展示数据，验证全部数量、记录键、定义与原始来源一致。JSON 安全嵌入 HTML，保留原始 MCP 响应内容和状态。
2. **浏览器行为检查**：在 Python 生成的实际 HTML 中检查独立 JavaScript 生成的卡片与 SVG 图表、名称和数值、来源记录、提示与点击、键盘操作及窗口缩放。页面提供实际展示结果记录 `window.EurekaIntelligenceCharts.receipts`，检查时逐项与嵌入数据比较。
   - **维度选择检查**：核对 `dimension_selection` 与其原始选择文件、真实配置及候选数据一致。公司和分类趋势按顺序进入 `visual-trend-row`，交叉图的 `dimension` 使用 `company-route:<field_key>`，并保留 `source_dimension`；对应面板分别标记 `company-trend`、`category-trend`、`company-cross`。检查桌面两张趋势图并排、手机纵向以及交叉图在下方，交叉字段不存在时按产品线和其他技术字段继续检查。没有真实 `level` 的验证只能证明 AI 重要性选择路径。
   - **历史期次检查**：对没有指定交叉气泡的时间维度，逐项核对 `receipts` 中的 `periods`、`points`、`signature`、`population_kinds`、`omitted_kinds`、`coverage`、`excluded_periods` 和 `continuous_basis_confirmed`。有两个及以上有效期次时，`presentation` 为 `line`，每个公司或分类对应一条实际曲线，实际图形必须包含这些期次；缺少配置版本时依然包含历史数量，`continuous_basis_confirmed` 仅记录历史配置依据是否已确认。核对滚动图例、系列选择、数据点与数值标签、真实点击后的月份和资料列表。仅有一个有效期次时核对实际日期与单期表达。缺失周期、不同字段定义、未知数量不得生成零值；分类覆盖完整的实际零值允许显示。定义比较与来源重算由历史模块维护，浏览器只执行展示选择。
   - **交叉气泡检查**：指定方向的 `presentation` 为 `bubble`、`scope` 为 `range`，替换该方向原有时间图或分布图。核对 `range`、`periods`、`company_dimension`、`field_key`、`points`、`classified_count` 与 `eligible_count`，独立从全部原始专利的申请人与分类成员计算交集并跨期去重，比较每个气泡的记录键和数量。核对页面省略期次选择器、面积与数量成正比、统计范围正确；通过真实气泡点击检查汇总资料列表、每条资料的来源期次、跨期重复身份只出现一次及完整原文。单期资料同样使用其完整范围。检查其他时间图继续按原期次显示，不以程序触发点击事件代替真实图形点击。
   - **图表列表检查**：使用真实图形点击，逐项核对右侧抽屉中的资料键、标题、所属期次与列表数量；正文优先使用原始 `technical_title`，缺失时核对原始摘要，两者均缺失时核实没有空白正文。检查长文字滚动、手机宽度、关闭操作、焦点恢复及打印，来源响应校验值保持相同。
3. **页面检查**：完成整页设计校验，检查桌面、手机和打印。核对统计卡片在 Summary 前，数字和标签上下居中排列，默认来源弹窗关闭；检查来源打开、Escape、关闭及焦点恢复。图表不得导致整页横向溢出，打印保留统计卡片、图表与数值。遵守用户关于视觉功能的限制，使用 DOM、布局和交互检查，并说明实际覆盖范围。
   - **顶部卡片检查**：按顶部统计卡片模块核对实际数量、资料条数与项目数量、同一目标期、部分解读覆盖提示及缺失字段省略。分析面板中的分类卡片不增加顶部数量；项目数量卡片先显示分组，继续进入对应资料列表。
   - **统计面板层级**：`assets/charts.css` 统一维护透明面板背景、1px 边框、8px 圆角和深蓝标题；桌面面板内边距 20px，手机 16px。图表滚动区域采用透明背景与 4px 圆角，整体使用章节底色。统计卡片保持固定宽度，图表配色和数据来源继续遵循本模块要求。
4. **交接输出**：将可选的 `charts.json`、Python 生成的 HTML、来源与页面检查结果交给报告模块。没有修改服务端配置或历史任务。

## 输出与完成条件

- `charts.json` 使用 `schema_version=3`，包含候选维度、实际数量、按类型保存的分类成员与评分完整性、来源记录索引、期间状态、实际返回的比较依据及原始文件路径和 SHA-256；HTML 内置相同数据和独立的前端展示代码。旧派生文件通过原始响应重新生成，不能只修改版本号。
- 实际展示的每个数值都能追溯到去重后的记录；少量项目采用卡片，多项比较使用图表，缺失与未知保持空缺。
- Python 生成流程及本期完整性检查通过，浏览器完成实际展示检查，原始响应保持不变。
